# board-capture

Rokid 眼镜板书捕获智能体（AIUI Agent）。

## 身份

一个运行在 Rokid 眼镜上的「板书捕获」助手，解决上课、开会时黑板
白板上的字又远又多、老师讲完就擦、手抄根本跟不上的问题。它的做法
是：你看向板书拍一张长焦照片，眼镜把这张照片作为图片发给主机大
模型读出来——转写全文 + 一句提纲——你核对无误后存进提纲清单，
下课/散会时一键按拍摄顺序把所有提纲朗读出来。它是本系列第一个
真正「读照片」的 Agent，走的是官方给出的读字路径，不是 OCR。

## 能力

- 拍（SNAP）：看向板书点 SNAP，用
  `ImageCapture.takePhoto({mode:'telephoto'})` 长焦拍下整块板
  （不可用时回退 wx.media CameraContext，同 DI01）。同时记录
  当时的头部朝向（AbsoluteOrientationSensor 四元数算 yaw，
  无传感器时如实记 `---`，不编造）与时间（一处快照取日期 +
  时间，同 DI38 的时钟纪律）。照片 Blob 只留在内存里等 READ，
  **从不落盘**：wx 同步存储存不下照片，本 Agent 也从不把照片
  写进任何存储——最终留下的只有文字。
- 读（READ）：把照片 Blob 经 `arrayBuffer()` + 分块
  `String.fromCharCode` + `btoa` 编码为 data: URL（转码失
  败报裸码 E2005），作为 user 消息的 `{type:'image_url'}` 内容
  连同一段文字指令一起发给主机 `LanguageModel`（多模态结构化
  content 只允许出现在 user 角色，system 提示只经
  `initialPrompts` 首条设置——档案 §2.9）。调用前先查
  `availability()`，用完 `destroy()` 会话。提示词要求逐行忠实
  转写、看不清处标 `[?]`、不许发明照片里没有的内容，并按
  `SUMMARY: <一句中文提纲>` + `TEXT:` 两段式返回；解析按行
  salvage（标签漂移时第一条无标签行作提纲、其余作转写），
  空回复视为失败。返回的文字在屏幕上标注
  「LLM READ - may misread, verify against the board」，
  **从不自动保存**——机器读数先过你的眼睛，你点了 KEEP 才
  算数。
- 口述提纲（DICT）：READ 之外的另一条路，也是所有失败时的
  兜底（即审计前原案的设计）。先按文档方式用
  `getUserMedia({audio:{captureSource:'microphone',
  microphoneMode:'wearer'}})` 做佩戴者模式麦克风可用性
  检查（开流、读回 settings、立即停掉全部轨道——这只是
  检查，检查流不是识别的输入，也不改变识别听到什么），再
  用宿主 SpeechRecognition（zh-CN）在它自己的麦克风上一
  次性识别；检查结果单独占一行 `MIC CHECK:`，聆听状态行
  写明 `(host ASR)`。听到的一句提纲**原样**保存为你的提纲，
  并且**优先于**大模型的提纲（KEEP 时你的话赢）。没有
  SNAP 过也能直接 DICT——生成一条无照片的提纲记录。主机
  没有识别能力时如实 SKIP，改走内置预置提纲轮换，绝不假
  装在听。
- 存档（KEEP）：唯一能把一条记录落盘的动作。存
  {序号， 日期， 时间， 朝向， 提纲， 转写， 来源} 入 wx
  同步存储（key `boardCaptures`，按拍摄顺序，最多 8 条，
  超限丢弃最旧一条并在状态行明说丢了哪条，不静默丢弃）。
  提纲来源三选一，全部如实标注：你的口述（DICT）> 大模型
  的一句提纲（LLM）> 两者皆无时记 `(no summary)`（NONE）。
  点头（头部稳定时）只在「已有读数或口述提纲待存」时等同
  KEEP——点头从不拍照、从不发起 READ。
- 提纲朗读（OUTLINE）：把存好的提纲按拍摄顺序拼成
  「第1张：……。第2张：……」用 speechSynthesis 朗读一遍；
  从不设置 `utterance.lang`（宿主不采纳该属性，档案 §2.6），
  它是合成语音朗读，不是真人录音。
- DEMO：内存里播入 2 条标注 DEMO 的记录（二次函数两块板）
  加 1 条标注「LLM READ (DEMO)」的待存读数（动量守恒例题，
  照片字节数为 0 并标注 DEMO），三处时间由一次时钟快照纯
  算术推导；不用相机、不用麦克风、不写真实存储；CLEAR 退
  出后恢复你真实的提纲。

## 行为边界

- **没有 OCR 这回事**：运行时不存在文字识别 API（档案
  §4.3）。本 Agent 读板书走的是官方路径——telephoto 拍照 +
  LLM 图片输入（§2.3 / §2.9）；照片经 data: URL 送入模型
  在文档里是成立的，但**宿主真机是否真的接受 image_url /
  data: URL，未经真机验证**（见 README「未验证」第一
  条）；FileReader 已实证不存在于本运行时（E2005），转
  码不依赖它。所以每条失败路径都留了一条能
  用的记录：模型不可用、转换不可用、模型报错、wx 回退照片
  没有 Blob 可转——全部如实落到对应状态，并提供 DICT 口述
  兜底，绝不把失败包装成读数。
- **机器读数必须核对**：大模型读板书会读错（公式、数字、
  生僻字尤其），提示词要求它看不清就标 `[?]`、不许编造，
  但这不是保证。READ 的结果先摆在屏幕上、标注来源与
  「may misread」，你看过、点了 KEEP 才进提纲；不对就
  DICT 用自己的话替换提纲，或干脆不存。
- **照片不留存**：照片只在内存里活到这条记录被 KEEP 或被
  下一张 SNAP 替换；落盘的永远只有文字（提纲 + 转写 +
  时间 + 朝向）。这一点界面常驻行写明
  「photos NOT saved」。
- **麦克风模式不塑造识别**（2026-10-24 能力边界审计口
  径）：wearer 检查流读完设置立即停轨，对宿主
  SpeechRecognition 的识别没有任何影响；文档与界面都不
  声称 wearer 模式让识别更准之类的效果。
- 相机/麦克风只在用户点 SNAP / DICT 时启动，用完立即停
  掉全部媒体轨道；不录音、不上传照片给任何服务器——图片
  只随 READ 的那一次请求发给主机大模型（宿主自有通道）。
- 声明权限：CAMERA（长焦拍板书，照片仅内存中转）与
  RECORD_AUDIO（佩戴者模式麦克风检查 + 提纲的一次性识
  别）；朗读走系统 TTS，不占权限。

# teleprompter-gaze

Rokid 眼镜凝视提词智能体（AIUI Agent）。

## 身份

一个运行在 Rokid 眼镜上的「视线内提词」助手，解决演讲、录视频、
上台发言时忘词的问题——稿子在纸上、手机里、提词器屏幕上，
看一眼就得低头，眼神一离开听众，气势就散了。它的办法是
眼镜独有的：把稿子放在你的视线正中央，当前段大字、下一段
小字预览，你抬着头讲，点头就翻段。它不替你写稿、不替你讲，
只负责让稿子一直在你眼睛里。

## 能力

- 稿子（内置 SAMPLE + 你口述的）：打开先有一篇 4 段的内置
  示例演讲（全程标注 SAMPLE），让你立刻能试提词。点 DICT
  口述，一次一段：先按文档方式用 `getUserMedia({audio:
  {captureSource:'microphone', microphoneMode:'wearer'}})`
  做佩戴者模式麦克风可用性检查（开流、读回 settings、立即
  停轨，结果单独记在 `MIC CHECK:` 行——这只是检查，检查流
  不是识别的输入），再用宿主 SpeechRecognition（zh-CN）在
  它自己的麦克风上一次性识别。听到的话**原样**存下（只去
  首尾空白，同 #21 / #36 / #37 的逐字纪律）——你说错了就是
  错的稿，核对屏幕就行。第一次口述会开启「你的稿子」并
  持久化为纯文本进 wx 同步存储（key `prompterScript`，
  上限 12 段）；SAMPLE 永远不会被当作你的稿子存下（加载与
  保存路径都有断言把关）。**没有文件导入这回事**——运行时
  没有把外部稿件读进来的通道，界面与 README 都明说：稿子
  只能来自内置示例和你的口述。
- 提词（当前段大字 + 下一段小字预览）：进度行「段 3/8」，
  翻段有三种等效方式——头部稳定时点头（`onHeadGesture`
  nod）、单击触控板（Enter)、下滑动（ArrowDown)；上滑动
  （ArrowUp）回上一段。翻到最后一段之后是「讲完了」终态：
  SPEAK 朗读总结（一共几段、用时多久）。用时由页面 500 ms
  一拍的 tick 累计（不反复采样 Date，同 #38 / #42 的时钟
  纪律——预览宿主的虚拟时钟在样本间漂移，tick 计数不受
  影响）；讲完后总时长冻结，界面标 `(final)`，BACK 回最后
  一段会恢复计时显示。SPEAK 在提词中是把当前段朗读出来
  给你练（TTS 从不设置 `utterance.lang`，宿主不采纳该
  属性，档案 §2.6）。
- 自动跟随（AUTO，尽力而为的字面匹配）：打开 AUTO 后一轮
  接一轮地听——每轮先做佩戴者模式可用性检查（停轨之后
  宿主识别才开始，顺序有断言证明），再用宿主
  SpeechRecognition 识别一轮。识别到的文本先归一化（去掉
  空白与中英文标点），然后在**当前段与后面两段**里找：你
  说的话的尾巴（至少 4 个归一化字符）如果原样出现在某一段
  里，就认为你讲到了那一段，提词跳过去，事件行写明
  「AUTO matched → 段 N (literal match)」；找不到就原地
  不动，事件行写明「no literal match - nod to advance」。
  这是**逐字比对**，不是语义理解：换个说法、记错词、识别
  出错，都会跟丢——跟丢了手动翻段永远有效，AUTO 的开关
  本身也是手动的。跟随命中的同时累计语速读数：命中推进的
  字符数 ÷ 两次命中之间的 tick 时长 = 约 X 字/分，界面
  写明样本数（from n matches）并标注「readout only」——
  它只是给你看的读数，不反过来控制任何东西。宿主识别
  报致命错误（not-allowed / service-not-allowed /
  audio-capture）或连续失败时，AUTO 会**自己关掉**并在
  AUTO 行写明原因，绝不装作还在跟随；页面隐藏/卸载同样
  停掉识别。
- 手势优先（档案 §3.2.1 触控板手势）：单击（Enter）= 情景
  主操作（AUTO 开着但没有轮次在跑时 = 开一轮聆听；讲完
  时 = 朗读总结；其余时候 = 前进一段）；滑动 Down = 下
  一段、Up = 上一段；双击（Backspace）= 返回，由宿主
  处理；头部稳定时点头 = 前进一段。点头从不开 AUTO、
  从不口述、从不朗读。屏幕保留 6 个按钮（NEXT / BACK /
  AUTO / DICT / SPEAK / DEMO），与手势等效或为手势纪律
  不代办的动作留明确入口，README「手势映射」逐个说明。
- DEMO：载入 SAMPLE 稿（内存中），把一句**原样摘自第 3
  段**的种子文本喂进与真实 AUTO 完全相同的匹配路径，于是
  提词当场跟随到第 3 段、事件行标注「DEMO AUTO matched」；
  退出 DEMO 后恢复你真实的稿子与进度，演示全程不写任何
  存储。

## 行为边界

- **AUTO 是尽力跟随，不是保证跟随**：它只做归一化后的
  逐字子串匹配——你即兴发挥、跳段太多（超过往后两段）、
  环境吵、识别把词听错，都会匹配不上。匹配不上时它如实
  停在原地并告诉你，你点头/点按随时接管。任何文案都不
  声称它「听得懂你讲到哪了」——它只认字面对得上的尾巴。
- **没有稿件导入**：不能从手机、文件或云端把现成稿子导
  进来。稿子的来源只有两个，都写在界面上：内置 SAMPLE
  （示例，不是你的稿）与你亲口口述的段落（原样保存、
  只存本机）。口述录入就是目前诚实的录入方式。
- **麦克风模式不塑造识别**（2026-10-24 能力边界审计
  口径）：wearer 检查流读完设置立即停轨，对宿主
  SpeechRecognition 的识别没有任何影响；AUTO 与 DICT
  的每一轮都是先停检查流、再开宿主识别，顺序由测试
  断言。文档与界面不声称 wearer 模式让识别更准。识别
  错了，AUTO 会跟丢、DICT 会存下错字——DICT 的稿子摆在
  屏幕上正是让你核对的，讲之前请看一遍。
- **语速只是读数**：PACE 由命中样本算出，样本少时抖动
  很大；它不调整提词速度（提词根本没有自动滚动这回事
  ——翻段永远由你或一次字面命中触发），不做任何承诺。
- 没有后台：页面关掉就没有提词、没有聆听；AUTO 只在
  页面打开、且你亲手打开它之后才听。麦克风只在 DICT /
  AUTO 轮次期间由宿主识别使用，本 Agent 不录音、不保存
  音频；稿子只存本机 wx 同步存储的文本，不上传。
- TTS 从不设置 `utterance.lang`。声明权限只有
  RECORD_AUDIO（佩戴者模式麦克风可用性检查 + 段落口述
  与 AUTO 跟随的宿主识别）。

# sign-reader

Rokid 眼镜远牌读牌智能体（AIUI Agent）。

## 身份

一个运行在 Rokid 眼镜上的「远牌读牌」助手，解决站牌、登机口、
菜单牌、路牌太远太小看不清的问题：公交站牌在马路对面，登机口
信息在通道尽头，菜单挂在柜台上方——走近看往往来不及或过不去。
它的做法是：看向牌子拍一张长焦照片，眼镜把照片作为图片发给主
机大模型读出来——最重要的一行（KEY）放大显示、全文在下——再
让你把你自己读到的关键信息说出来，两边逐字比对，一致就放心，
不一致就以你的眼睛为准。它走的是官方给出的读字路径，不是
OCR；而且机器读数永远要过你这道核对。

## 能力

- 拍（SNAP）：看向牌子点 SNAP，用
  `ImageCapture.takePhoto({mode:'telephoto'})` 长焦拍下牌子
  （不可用时回退 wx.media CameraContext，同 DI01/DI39）。同时
  记录当时的头部朝向（AbsoluteOrientationSensor 四元数算
  yaw，无传感器时如实记 `---`，不编造）与时间（一处快照取
  日期 + 时间，同 DI38/DI39 的时钟纪律）。照片 Blob 只留在内
  存里等 READ，**从不落盘**，本 Agent 也**不写任何存储**——
  牌子是当下的事，会话结束一切消失。
- 类型（TYPE）：READ 之前先选牌子类型——站牌 / 登机口 /
  菜单 / 路牌 / 其他——轮换切换，写进给大模型的文字指令作
  为上下文，让它知道该找哪一类关键行（车次方向、登机口号、
  菜品价格、出口方向）。
- 读（READ）：把照片 Blob 经 `arrayBuffer()` + 分块
  `String.fromCharCode` + `btoa` 编码为 data: URL（转码失
  败报裸码 E2005），作为 user 消息的 `{type:'image_url'}` 内
  容连同一段文字指令一起发给主机 `LanguageModel`（多模态
  结构化 content 只允许出现在 user 角色，system 提示只经
  `initialPrompts` 首条设置——档案 §2.9）。调用前先查
  `availability()`，用完 `destroy()` 会话。提示词要求逐行
  忠实转写、看不清标 `[?]`、不许发明照片里没有的内容，并
  先挑出最重要的一行原样摘出，按 `KEY: <关键行>` +
  `TEXT:` 两段式返回；解析按行 salvage（标签漂移时第一条
  无标签行作 KEY、其余作转写），空回复视为失败。KEY 行以
  页面上最大的字号显示，全文在下，整段标注「LLM READ -
  may misread」。
- 核对（DICT，你的眼睛作交叉验证）：点 DICT，先按文档方式
  用 `getUserMedia({audio:{captureSource:'microphone',
  microphoneMode:'wearer'}})` 做佩戴者模式麦克风可用性检查
  （开流、读回 settings、立即停掉全部轨道——这只是检查，
  检查流不是识别的输入，也不改变识别听到什么），再用宿主
  SpeechRecognition（zh-CN）在它自己的麦克风上一次性识
  别；检查结果单独占一行 `MIC CHECK:`，聆听状态行写明
  `(host ASR)`。你说出的关键行**原样**显示在 `YOU READ:` 行。
  两边都有时做**字面比对**：轻量归一化（去掉全部空白、去掉
  尾部标点）后逐字比较，显示 `MATCH ✓` 或 `DIFF ⚠`——比对
  只是比字面，不理解语义，界面常驻说明这一点。主机没有识
  别能力时如实 SKIP，改走内置预置行轮换，绝不假装在听；
  没有 SNAP 过也能直接 DICT，你的口述行直接成为大字 KEY
  （YOU READ 模式）。
- 朗读（SPEAK）：把 KEY 行用 speechSynthesis 念出来，并明
  说来源：两边一致念「核对一致，牌子上写的是：…」；不一致
  时**先念你的版本**并说明「机器读的是…，请以你的眼睛为
  准」；只有机器读数时念之前先声明「机器读数，可能读错」。
  从不设置 `utterance.lang`（宿主不采纳该属性，档案
  §2.6）。
- 点头纪律：头部稳定时点头只等同 SPEAK，且只在已有 KEY 行
  （机器读数或你的口述）时——点头从不拍照、从不发起 READ、
  从不口述。
- DEMO：内存里播入一条标注 DEMO 的登机口读数（KEY 为
  「12 号登机口 · 东京羽田 · 15:40 开始登机」，转写标注
  DEMO、照片字节数为 0）；DEMO 中点 DICT 播入的「你读到
  的」是门号改成 13 的一行，于是 DIFF 状态可完整预览；
  CLEAR 退出后恢复真实会话，全程不写任何存储。

## 行为边界

- **没有 OCR 这回事**：运行时不存在文字识别 API（档案
  §4.3）。本 Agent 读牌走的是官方路径——telephoto 拍照 +
  LLM 图片输入（§2.3 / §2.9）；照片经 data: URL 送入模型
  在文档里是成立的，但**宿主真机是否真的接受 image_url /
  data: URL，未经真机验证**（见 README「未验证」第一
  条）；FileReader 已实证不存在于本运行时（E2005），转
  码不依赖它。所以每条失败路径都留了一条能
  用的路：模型不可用、转换不可用、模型报错、wx 回退照片
  没有 Blob 可转——全部如实落到对应状态（失败原因写在
  READ 行上，不会被渲染覆盖），并提供 DICT 兜底：你的眼
  睛 + 你的口述在任何情况下都能把关键行顶到大字位。
- **机器读数必须核对**：大模型读远牌会读错——门号、车次、
  价格、时间都是高危区。KEY 先摆在屏幕上、标注来源与
  「may misread」；DICT 核对的设计就是承认机器会错：两边
  不一致时 SPEAK 先念你的、界面明说以你的眼睛为准。
- **字面比对不是理解**：CHECK 只做归一化后逐字比较。格式
  差异（分隔符、繁简、数字写法不同）会被判 DIFF——这是往
  安全方向错：宁可多提醒你核对，不假装一致。
- **什么都不存**：本 Agent 不写任何 wx 存储。照片只在内存
  里活到这块牌子被下一张 SNAP 替换或会话结束；读数、口述
  都随会话消失。界面常驻行写明「photos NOT saved ·
  nothing is stored」。
- **麦克风模式不塑造识别**（2026-10-24 能力边界审计口
  径）：wearer 检查流读完设置立即停轨，对宿主
  SpeechRecognition 的识别没有任何影响；文档与界面都不
  声称 wearer 模式让识别更准之类的效果。
- 相机/麦克风只在用户点 SNAP / DICT 时启动，用完立即停
  掉全部媒体轨道；不录音、不上传照片给任何服务器——图片
  只随 READ 的那一次请求发给主机大模型（宿主自有通道）。
- 声明权限：CAMERA（长焦拍远牌，照片仅内存中转）与
  RECORD_AUDIO（佩戴者模式麦克风可用性检查 + 你读到的关
  键行的一次性识别）；朗读走系统 TTS，不占权限。

# allergen-guard

Rokid 眼镜过敏守卫智能体（AIUI Agent）。

## 身份

一个运行在 Rokid 眼镜上的「配料表逐项核对」助手，解决过敏/忌口
人群每买一样东西都要眯眼读配料表、漏看一个词就可能进医院的
问题。眼镜不替你读标签——它做的是另一件事：把你的忌口清单
逐项摆在你眼前，一项一项问你「含这个吗？」，你亲眼看着配料表
回答；只要有一项你答「含」，它立刻大声警告「不要买」；全部
走完、全部答「未见」，它才放行。

## 能力

- 忌口档案（PROFILE）：8 种常见过敏原（花生 / 牛奶 / 鸡蛋 /
  麸质小麦 / 大豆 / 坚果 / 海鲜甲壳类 / 芝麻），PROFILE 逐个
  切换、TOGGLE 开关，只需设置一次，存入 wx 同步存储
  （key `allergenProfile`），下次打开自动载入。出厂默认
  花生 + 牛奶为 ON（界面标注 default），请按自己的情况改。
- 长焦拍照（只作当场记录提示）：LOOK 用 `getUserMedia` 取流后以
  `ImageCapture.takePhoto({mode:'telephoto'})` 拍下配料表面板
  （不可用时回退 wx.media CameraContext），界面只显示字节数
  并标注 record only。照片本身不保存：拍完只取字节数，Blob
  随即丢弃，日后无法翻看；照片不被读取，更不会被识别。
  真正持久保存的只有忌口档案；本次结论与逐项答案只在
  结论页当场显示，不存档。
- 逐项核对（CHECK）：NEXT 开始核对，只走你打开的忌口，
  一次一个，大字问「含『花生』吗？看配料表再答」。你用
  FOUND（含）/ CLEAR（未见）/ UNSURE（看不清）三键先选
  答案，再按 NEXT 或 Enter 确认记入这一项；没有捷径跳到
  OK——必须逐项走完。
- 点头的安全语义：头部稳定（`onOrientationStabilityChange`）
  后点头（`onHeadGesture` nod）：在 HOME 触发 LOOK 拍照；
  在核对中只「确认已选的答案」，绝不替你作答、更绝不等于
  CLEAR；没选答案时点头会被忽略并提示先选。结论页点头
  = 放行进入下一件商品。
- 微量行（TRACE）：全部忌口答完后多问一句「有『可能含
  微量 / 同生产线』提示吗？」——真实食品标签的 may-contain
  警示行。答 YES 时，即使配料逐项全 CLEAR，结论也会从 OK
  降级为 CAUTION。
- 结论与语音警告（自动朗读）：任一 FOUND →
  「DO NOT BUY — 含X」并立即 TTS 朗读「注意，这个含X，
  不要买。」；任一 UNSURE → CAUTION「有看不清的成分，
  别冒险」，并附重度过敏指引「看不清就按含有处理，不要
  买」；仅微量行 YES → CAUTION；全部 CLEAR 且无微量
  提示 → OK「你的忌口都不在配料表里」。SPEAK 可重读
  当前问题或结论。
- DEMO：载入演示档案（花生 + 牛奶，仅内存，不覆盖你存
  的档案），模拟一件花生=含、牛奶=未见、无微量行的商品，
  直接走到 DO NOT BUY 结论页，方便在没有相机的预览环境
  里看到警告态。

## 行为边界

- **眼镜从不读标签，读标签的是你**：AIUI 运行时没有 OCR，
  拍下的照片也没有任何链路变成成分结论。配料表由佩戴者
  亲眼读，逐项回答由佩戴者给出；你读错了，它抓不到你。
  界面、代码注释与 README 全程如实标注
  「photo = record only, the agent does NOT read the label」，
  绝不声称从照片识别出了成分。
- 本 Agent 不是医疗建议，不判断「吃下去会不会过敏」：它
  只机械汇总你亲眼确认的答案。重度过敏人群对 UNSURE 的
  正确处理是按含有对待、不要买——这行指引写在结论页上。
  无法确认成分的商品，宁可不买，并咨询医生/药师。
- 相机只在用户点 LOOK 或点头时启动，拍完立即停掉全部
  媒体轨道；页面卸载时同样清理。
- 主机没有相机时 LOOK 显示 FAIL 并写明原因，不伪造照片；
  核对流程本身不依赖相机，没有照片也能逐项走完。
- 不上传照片，不保存拍摄内容；照片只取字节数用于状态
  显示。唯一持久化的是你的忌口档案（过敏原开关列表）
  存在本机 wx 同步存储。

# site-patrol

Rokid 眼镜工地巡检智能体（AIUI Agent）。

## 身份

一个运行在 Rokid 眼镜上的「工地/仓库巡检清单」助手，解决巡检要
逐项看、逐项记、双手却拿着工具的问题：消防器材到没到期、安全出
口堵没堵、配电箱有没有异味——靠脑子记，走到第三个点就漏。它
的做法是眼镜独有的：把固定的六个检查点绑在你的头部朝向上，逐
个领你看向它们；而且这一款的完成标准比入住巡检（DI43）更严：
一个检查点必须**状态、照片、确认三件齐全**才算完成，缺哪件，
它当场告诉你缺哪件。全六项完成，一轮巡检存档为文字记录。

## 能力

- 朝向读取：AbsoluteOrientationSensor（约 5Hz）四元数算 yaw 朝向角，
  界面如实标注来源 SENSOR / DEMO / NONE；无传感器时不编造朝向，
  MARK 登记会拒绝并说明原因（同 DI07 / DI28 / DI30 / DI43）。
- 检查点（固定 6 个）：消防器材 / 安全出口 / 配电箱 / 防护栏 /
  物料堆放 / 警示标识，每个都带一句你亲眼核对的具体线索（如消
  防器材「灭火器在位、压力表在绿区、有效期未过，前面无遮挡」、
  配电箱「箱门关好、无异响异味，周边半米内无易燃物」）。
- 登记朝向（MARK）：看着检查点点 MARK（或单击触控板），把
  {检查点名， 朝向°} 存入 wx 同步存储的本机记录（key
  `sitePatrolRounds`，与当前轮次状态、已归档轮次一起存，onLoad
  载入、每次变更与 onUnload 落盘）。同一个点重新登记覆盖旧朝
  向。**朝向跨轮次保留**：同一个工地每轮巡检站位差不多，登记
  一次、每轮复用，NEW 开新轮不清朝向。朝向只是指引与凝视确认
  的前提，不是必需：没登记的点靠眼睛找、点按走完三件，照样
  能完成。
- **三件齐全才算完成（本 Agent 的核心规则）**：每个检查点要同
  时有三件才记 DONE，顺序不限：
  1. **状态**：点 OK 记「没问题」，或点 ISSUE 记「有问题 +
     一条备注」；
  2. **照片**：点 PHOTO 拍一张 default 模式照片——这是本
     Agent 的记录规则要求，但照片只是**会话内记录**（证明你
     当时站在这个点跟前），从不落盘、从不归档（见行为边界）；
  3. **确认**：看向该点、头稳住连续满 2 秒的凝视确认（记
     `gaze`)、正对着它点头（记 `nod`)、或点 OK（记 `tap`)。
  缺件如实显示在清单行与指引框（「待：状态/照片/确认」、
  「还差：照片」），单击（Enter）确认后若仍有缺件，会把缺件
  朗读出来——绝不出现「看着办完了、其实少一件」的假完成。
- ISSUE（登记问题）：先做佩戴者模式麦克风可用性检查（开流、
  读回 settings、立即停轨，结果单独记在 MIC CHECK 行；检查
  流不是识别的输入，也不改变识别听到什么——**佩戴者模式不
  抗噪、不塑造识别**，见行为边界），再用宿主
  SpeechRecognition（zh-CN）把你说的问题**原样**记下（记
  `asr`)。主机没有识别能力、或识别报错未出结果时如实 SKIP，
  改走内置预置词条轮换（灭火器过期 / 通道堵塞 / 围栏破损 /
  标识缺失，记 `chip` 并标注预置），绝不假装在听。ISSUE 只
  填状态一件：不确认、不拍照——三件仍要分别齐全。
- 漏检指引（相对方向，永不报东南西北）：未完成项按登记朝向
  给出 8 向箭头与「TURN: RIGHT 40°」；SPEAK 朗读进度时逐项
  报还差哪几件、最近的未完成项在你哪个方向。LIST 直达下一
  个未完成项。
- 轮次归档（ROUNDS）：六项全部完成即收轮——汇总（OK n ·
  ISSUE m，问题备注逐条）自动 TTS 朗读一次，同时把这一轮的
  {日期、时间、每项状态/备注/确认方式/时间} 作为**纯文字**
  存档进 `sitePatrolRounds`，最多存 5 轮，超了丢最旧一轮并
  在事件行明说。收轮后再翻转某项状态，只更新同一份存档快
  照，不重复归档、不重复朗读。NEW 两段确认开新一轮：清状态、
  备注、确认与会话照片，**保留朝向与已归档轮次**；未完成的
  半轮不归档，开新轮即放弃。
- 手势优先（档案 §3.2.1 触控板手势）：单击（Enter）= 情景主
  操作：已收轮则朗读汇总；选中项已完成则跳下一个未完成项；
  未登记则登记朝向；其余 = 点按确认该项（OK 路径），确认后
  仍有缺件则朗读缺件。滑动（ArrowUp/Down）= 前后移动选中
  项。双击（Backspace）= 返回，由宿主处理。头部稳定时点头
  (nod）= 仅当你正对着选中检查点（登记朝向在 ±25° 内）时填
  它的确认一件；点头从不设状态、从不登记问题、从不拍照、
  从不登记朝向。屏幕保留 8 个按钮（MARK / OK / ISSUE /
  PHOTO / LIST / SPEAK / DEMO / NEW），与手势等效或为手势
  纪律不代办的动作留明确入口，README「手势映射」逐个说明
  了保留理由。
- DEMO：内存里播入一个演示工地——3 个检查点绑上演示朝向
  30° / 110° / 200°，消防器材已三件齐全完成（状态 ok +
  照片 + 凝视确认），安全出口已登记一个预置词条问题（通道
  堵塞，只有状态一件、未完成），演示头部停在 200° 正对配
  电箱、头部稳定，配电箱的确认驻留定格在 1.0 秒供预览看清
  （真机上驻留按真实时间推进）；之后每点一次 DEMO 朝向
  +45° 并把定格驻留换到新锥形区内的点，转满一圈（8 步）后
  再点一次退出演示、恢复真实记录。DEMO 中 PHOTO 播入 0 字
  节的假会话记录并标注 DEMO。演示状态永不落盘、不归档；
  DEMO 中 NEW 被拒绝。

## 行为边界

- **它确认的是「你逐项看过、站到过、确认过」，不是「检查点
  本身没问题」**:灭火器压力够不够、栏杆牢不牢，靠的是你的
  眼睛和手，眼镜判断不了。Agent 只负责把六个点逐个摆到你
  面前、三件一件不落，并如实记下每件是怎么来的（状态是你
  定的、确认是 gaze/nod/tap 哪一种、问题是你的原话）。界面
  页脚、收尾朗读与 README 都如实写明。
- **照片不落盘、不归档**：AIUI 的 wx 同步存储存不下照片
  Blob(同 DI04 / DI22 / DI29 / DI43 的审计口径），本 Agent 要
  求拍照片是把它当作「你当时站在这个点跟前」的会话内凭据，
  页面关掉即消失；任何落盘数据、任何一轮存档里都不含照片
  字节（已由测试断言）。需要留证（比如向施工方追责）请用手
  机拍——界面照片行常驻写明这一点，不让你误以为眼镜里存了
  证据。
- **麦克风模式不塑造识别**（2026-10-24 能力边界审计口
  径；原计划行里的「wearer 麦抗噪」说法不成立，在此正
  面纠正）：wearer 检查流读完设置立即停轨，对宿主
  SpeechRecognition 的识别没有任何影响——它不降噪、不提
  高识别率，工地再吵，识别听到的还是宿主麦克风听到的。文
  档与界面都不声称 wearer 模式让口述更准之类的效果。口述
  原样入账，识别错了就是错的备注——汇总朗读正是让你核对
  的一环。
- 朝向只对你登记时站的位置成立（同 DI07 / DI28 / DI43 的几何
  边界）：登记的是「从我站的地方看向这个检查点」的方向；
  巡检时站回登记位置附近慢慢转头，锥形区与指引才有意义。
  换一个站位，几何关系就变了——跨轮次复用朝向的前提也是
  你每轮站在差不多的位置。
- 朝向缺失（SRC NONE 且非 DEMO）时拒绝登记，绝不编造朝
  向；巡检本身不完全依赖朝向——没有传感器时仍可按清单逐
  个找、OK 设状态兼确认、PHOTO 拍照（三件里确认记 tap)。
- 归档只有 5 轮：更早的轮次被丢弃时事件行会明说；归档是本
  机文字记录，不上传、不同步，需要长期留存请自行抄录。
- TTS 从不设置 `utterance.lang`（宿主不采纳该属性，档案
  §2.6）。相机/麦克风只在用户点 PHOTO / ISSUE 时启动，用完
  立即停掉全部媒体轨道；记录只存本机 wx 同步存储，不上
  传；DEMO 状态只在内存里，永不落盘覆盖真实记录、永不
  归档。

rodik的底座提供了丰富的能力，ai语音助手和默认的应用都覆盖了大多数场景，那么做agent智能体，无非就是做场景的harness，这样理解全面吗？不对的地方是什么

## Muse — 2026-10-29 08:13

大体对，但漏了三处关键的，漏掉就容易又做回薄功能点。

**对的部分**
底座已经把通用能力做完了：ASR、TTS、翻译、字幕、转写、提词、慧眼辨识、导航。Agent 再做一个功能点，本体就是默认功能加一层小扭转 —— 这就是冲突审计里一档 14 个的教训。所以 Agent 的价值确实不在实现功能，在编排。

**不对 / 不全的地方**

1. **不是 LLM 的 harness**
harness 这个词暗示中间有个强模型等你编排。Rokid 上不是：LLM 是宿主托管的，型号不暴露、tool call 不自动执行，API 是清单式的，查不到就不存在。实际建出来的精品，核心是写死的状态机 + 成套内容 + 传感器/手势编排，LLM 只是其中一步（比如拍照→data URL→读文字）。把它当 harness，会高估自由发挥，低估确定性流程。

2. **默认应用是广度覆盖，不是闭环覆盖**
它能翻译一句、辨识一次、转写一次，但无状态、无校验、不对结果负责。场景真正难的是后半段：进入→过程→出错恢复→验证→下次还记得。所以三关里的闭环关和厚度关（真实数据 / 成套内容 / 多步流程 / 跨会话记忆 / 集合总控至少两样）筛的正是这个 —— 没有这些，套壳就薄，首批精品 10 个被判薄合并成 5 个就是这么来的。

3. **漏了约束先行这一路**
路缘坡那批不是给已有场景套壳，是从底座没考虑的人和时刻反推的：手占满、不能开口、不能低头看屏时，默认的语音助手范式本身就失效了。这时 Agent 做的是发明新的交互组合 —— 凝视确认、点头开关、GPS 的 cardinal 方位管锚定地点、相对方向管眼前 —— 这是给底座补交互层，不是编排现有功能。

4. **还有一类根本不是场景**
benchmark、AV 系列、视频流探针这类，是去顶底座边界的：FileReader 不存在、mic 模式不作用于宿主 ASR，都是靠 Agent 实测出来的。harness 预设底座已知，这里恰恰相反。

更准的说法可能是：**Agent = 在底座通用能力之上，用确定性流程 + 成套内容 + 传感手势交互，对一个具体时刻的一个结果负责的闭环。** harness 是它的技术形态，产品定义是「对结果负责」——少了这句，就分不清场景 Agent 和一档冲突。

眼镜自带的助手，就像一个什么都会一点的人。你让它翻译，它翻一句；让它看，它看一眼；让它记，它记一下。帮完一下，它就走了。

## GO — 2026-10-29 08:23

游戏呢，和掌上游戏的最大特点是什么，哪些特点是不可取代的，注意手机也有陀螺仪也有传感器

## Muse — 2026-10-29 08:23

游戏这块，手机有陀螺仪这点你说得对 — 单看传感器，手机一点不差，甚至屏幕、性能、触控全都比眼镜强得多。如果只是把手机上「晃一晃、倾斜一下」的游戏搬到眼镜上，那眼镜没有任何不可取代，纯属吃力不讨好。

不可取代的不在传感器本身，在传感器**装在哪**。

**1. 手机的传感器量的是手机，眼镜量的是你这个人**
拿着手机倾斜，你的手在动，头没动，眼睛还是从外面看着一块屏幕，你甚至可以只甩手腕作弊。
眼镜戴在头上，你转头，画面跟着转，看的方向就是玩的方向。想作弊？你得真的把脖子转过去。所以眼镜游戏的分数是绑在身体真的动了没有上面 — 这也是头部游戏为什么敢做成活动脖子、找平衡这一类，手机做这个是假的，眼镜做是真的。

**2. 玩的时候不用拿出任何东西，也不用低头**
手机游戏再小，也要掏出来、解锁、低头、两只手捧着，人就从眼前的事情里退出去了。
眼镜本来就戴着，抬眼就开始，手一直空着，对面的人还能看见你的脸，你也还看得见路。一局三十秒，玩完人还在原来的事情里。这个「不退出」的状态，手机给不了 — 手机的本质就是把你的注意力收进那块屏里。

**3. 游戏场就是你眼前的真地方**
手机的摄像头是你用手举着对准的，像举着个取景框。眼镜的摄像头就是你的眼睛，你看到什么它看到什么。
所以眼镜游戏可以拿真实世界当棋盘：转头在房间里找东西、记住东边那棵树在哪再转回来指认、看着真人真物玩。手机也能扫一扫，但那是「举着设备去够世界」，眼镜是「世界本来就在你眼前」。

反过来说，眼镜输得很惨的地方也要认：单色绿、小画面、没法精细操作、玩久了脖子累还可能晕。所以它天生只能做慢的、小幅的、一小段一小段的游戏 —— 看一看、点点头、保持住、回正 —— 做不了手机那种一玩半小时的大游戏。

一句话：**掌上游戏是「你操作一个东西」，眼镜游戏是「你本人就是那个被操作的角色」。** 传感器到处都有，装在头上、和眼睛长在一起的，只有它。

## Muse — 2026-10-29 08:26

这个想法刚好把前面两件事扣上了：底座帮一下不行，得陪着办完；传感器到处都有，装在眼睛上才不可取代。MUD 可能是最适合眼镜的游戏形态，没有之一 — 因为 MUD 本来就不要画面，只要文字。眼镜最惨的短板（单色绿、小屏、没性能）在 MUD 里全部不存在，它的长板（看哪玩哪、手空着、耳朵听、嘴说话）全部用上。

人话讲这个游戏怎么成立：

**你站在一个真地方，拍一张照，这个地方就变成游戏里的一个房间。**
照片给大模型看，它把眼前写成 MUD 那种房间描述：这里是什么、有什么东西、往东南西北各通向哪。画面里的东西顺手变成游戏物件 — 自动贩卖机是卖药水的商人，长椅是坐下回血的点，神社是存档点。不是美术画出来的 NPC，是你眼前的真东西被给了个身份。

**任务就埋在这个房间里，验证靠你再看一眼。**
比如商人让你去找东边那个红色招牌。你真的走过去、转头看、再拍一张，模型认出招牌，任务完成。找东西靠走路和转头，交任务靠拍照对账 — 前面说的「身体作弊不了」「世界就是棋盘」，在这里全用上了。

**地图是你自己走出来的。**
每到一个新地方拍一张，就是一个新房间，和旧房间连起来。玩得越久，你的地图越大，而且这张图全世界只有你有 — 它就是你家、你上班的路、你常去的公园，长在你真实生活上面。这才是「大型」的正确打开方式：不是官方做了个大世界等人来，是每个人的世界跟着自己的脚长大。

得泼的三盆冷水，也都是实话：

一是它不是实时 AR。眼镜只能一张一张拍照，没有一直看着画面认位置的本事。所以房间是拍照那一瞬间定格生成的，东西搬走了它不知道，要靠你再拍一张更新。好在 MUD 是文字的，定格完全不违和。

二是模型看图会认错。招牌认错、东西看漏都会发生。所以任务判定不能装成百分之百准，认不准时要老实说认不准、让你换个角度再拍。这条之前拍照游戏系列已经立过规矩了。

三是「真人大型」得先降一格。眼镜自己撑不起很多人同时在线的世界，它连后台常驻都没有。能做的是异步的：你在某个地点留一个任务或一句话，下一个戴眼镜路过的人拍到这里，能接你的任务 — 像在全城藏纸条。大家不在同一个房间里打架，但共用同一张真实地图。这格降得值，异步反而和「地图慢慢长大」是一路的。

所以最小的一局是这样的：**拍照 → 生成房间和一个 NPC → NPC 给一个要在附近走着完成的任务 → 走过去拍照验证 → 奖励，并且这个房间存下来，下次路过还是它。** 这一局跑通，后面的全是往上加：房间连成图、NPC 记住你、别人留的任务。

这个已经不是小游戏了，它更像给真实世界写了一层文字皮肤。要不要我把这一局先写成一份能照着开工的设计稿，还是先在这里继续想？

## Muse — 2026-10-29 08:29

对，而且这条比游戏那条还硬 — 因为手机在这件事上先天残废：**你拿手机拍手，就先占掉一只手。** 胸前挂的相机能看见手，但角度是斜的。眼镜是唯一一个两只手在干活、它在正中间看着的设备。你低头看自己的手是人干活时最自然的动作，所以你看哪，它就拍到哪，不用瞄准。

但得先把边界说清，不然这个系列会做歪。眼镜看手，靠的是**拍照给模型看**，没有那种游戏机里的手部骨骼追踪。所以它能做的是「停下来看一眼」，做不了「一直盯着手的动作」。按可靠程度分三层：

**第一层：看手里拿的东西 — 最靠谱**
把东西拿到眼前这个动作，本身就成了一个标准用法，等于「递给眼镜看」。药瓶、调料、零件、要装箱的货、两件要比一比的商品。递过去，拍一张，认出来。
但注意：只做到「认出这是什么」就别做了，那是慧眼自带的事，重做就是浪费。这层必须往后多走几步才成立：认出来 → 跟手头的清单或标准对一对 → 告诉你下一步 → 你做完再递一次给它验。认只是中间一步，核对和验收才是这个系列干的活。
能落的场景全是手上有活的：照着单子拣货装箱别装错、做饭时拿起调料确认放没放过、修东西时举起零件确认型号和装的方向、吃药前举起药盒跟医嘱对一遍。

**第二层：看手本身摆成什么样 — 能做，要挑着做**
一张照片能判断的静态样子：有没有戴手套、握刀握工具的姿势对不对、手指比的是几。最后这个有点意思：**手指可以当一个不出声的输入**。吵的车间里喊不动、安静场合不方便开口、或者本来就说不了话的人，举手比个数字就选了，比个手掌就停了。手从「被看的对象」变成「不用说话的按钮」。
规矩还是一样：认完必须让你确认，它认错手指你得能纠回来，不能它说了算。

**第三层：看手连续的动作 — 做不了，别碰**
手语、手的轨迹、实时纠正你手往哪挪，这些要连续追踪，眼镜没这个本事，硬写进设计就是骗人。替代办法是把它切成一段一段的，这跟头部游戏的规矩其实是同一条：**做一步 → 举手给它看一眼 → 过了再做下一步。** 手工艺、编织、装配训练，全可以这么切。

所以这个系列真正的骨架就一句话：**双手是操作台，眼镜是站在你对面看着操作台、全程记账和验收的那个人。**

要我按这个骨架列一版系列清单吗？大概能拆三条小线：干活核对的、出声不便时用手输入的、一步一验学手艺的。

## Muse — 2026-10-29 08:30

这个比喻找得准 — 描红。 而且它正好绕开了眼镜最大的短板。

眼镜不会追踪你的手，所以它没法像游戏机那样「看着你的手纠正你」。但描红不需要老师盯着：纸上印一个淡淡的范字，你自己把笔描上去对齐。眼镜这里就是：**中间浮一个手印的轮廓，你把双手举到眼前，自己去跟它对齐，对齐的过程就是在学。** 系统只负责最后验收 — 你摆好了，点一下头，拍一张，模型看一眼像不像，像就翻到下一个印。

一整套忍术就是一条印的序列，边上放步骤正合适：子→丑→寅→卯……你做到第几个，边上就亮到第几个，做错了停在那一步重来。这就是前面说的「做一步、验一步」的切法，只不过切的是结印。

往游戏上长也很自然，分两档：
慢档是描红，照着学，不计时间；
快档是竞速，整条序列滚过去，看你多少秒结完、错几次。火影里结印本来就比速度，这个设定是原作自带的，不用硬编玩法。

而且这个样子不只结印能用，它是个通用的壳：中间一个范本、边上是步骤、手摆好了拍照验收。换一套范本图，就是手语练习；换一套，就是手指操、握笔姿势、编织的起手式。**结印是这个壳的娱乐版，手语是它的正经版。**

只有一盆冷水，而且是决定这东西成不成的那盆：结印的手指是交缠的，好几个印从正面看只差一根手指的位置，模型拍照认这种细微差别到底准不准，现在谁也不知道 — 简单手势比数字它行，这个难度高一档。所以真要开工，第一步不是做游戏，是先做个小试验：十二个基本印挨个摆、挨个拍，看它能认对几个。认对得多，这个系列成立；只认对一半，就把玩法改成只用它认得准的那几个印编序列。

还有个小提醒：真拿去提审，「火影」「某某忍术」这些名字是别人的版权，商店那关可能卡。自娱和试做没问题，上架版多半得换成泛称的忍者手印，印本身画出来教人摆，问题不大。

先回答存档那个问题，这个决定架构的地基：

**Rokid 没有给 Agent 留云端存档空间。** 我刚查了能力档案和官方 API 参考：官方给的存储全是本地的 — `localStorage`（每个智能体隔离的字符串存取）、wx 存储（同类，存 JSON）、还有一个持久文件存储入口但官方没给细则。Studio 那个云端只是发包用的，不是给你存玩家数据的。所以两条路：

- **单机阶段：存档就放眼镜本地**，放在智能体自己的隔离存储里，设计见下面。
- **联机阶段：云端要自己建。** 这事你已经有现成的路了 — rokidpost 那套 Cloudflare 前门就是自建后端，到时候存档同步和多人世界都挂在同类后端上，不用从零想。

**本地存档怎么设计（先记住四个要点，细则在启动词里）**
存档是一份带版本号的 JSON，按块分开存：一块玩家（等级、背包、钱），一块世界（你拍过的房间，一间房一块，单独存，地图再大也不会把一份存档撑爆），一块 NPC 和任务进度。**照片本身不存** — 一张照片的数据顶一百个房间的文字，只存模型看完照片写下的房间描述和判定结果。存档分两个槽轮换着写，写坏一个还有上一个能退回来。

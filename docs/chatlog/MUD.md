## Muse — 2026-10-29 15:17

就是 **MUD1** 本人——它既是第一款，也是最早那几年的绝对一哥，没有对手可言。

1978 年英国埃塞克斯大学的 Roy Trubshaw 写出原型，Richard Bartle 接手做大，就叫 *MUD*（Multi-User Dungeon），后来为了和品类名区分才叫它 MUD1。它火到什么程度：1980 年代只能半夜蹭大学主机的空闲时段玩，拨号端口还抢不上，抢不到的人干脆自己仿写，于是有了后面一整个品类；它授权到美国 CompuServe 后改名 *British Legends*，多年里都是平台上最赚钱的休闲产品之一。

一个小注脚：同期美国有个 *Milieu*（后来的 *Sceptre of Goth*）也差不多时间出现，谁先谁后学界至今没完全吵清。但「MUD」这个名字、房间+出口的世界结构、持久世界和升级体系，都是 MUD1 这一脉定的——我们现在做的这个，追祖宗就追到它。

## Muse — 2026-10-29 20:52

按我们平台的家底，多人只能有一种骨架：**眼镜之间不直连，全部人连同一个自建服务器，服务器是世界唯一的账本。**原因就三条硬约束：Agent 之间不能互调、眼镜上不能后台常驻、局域网直连不支持——所以不存在「两副眼镜互相发现、互相同步」这条路。具体实现分四块：

**1. 服务器（阶段 3 建）**
形态直接复用 rokidpost 已跑通的模式：Cloudflare Workers 当前门、D1 存数据，独立仓库独立域名。服务器管四件事：玩家身份、云端存档、共享房与审核队列、多人会话与回合定序。MUD 的数据全是文字和 JSON，一间房几 KB，早期这个量级绰绰有余；将来回合会话多了，可给每个会话配一个 Durable Object（Cloudflare 的单例对象，天生适合「一个会话一份状态、按序处理」），那是阶段 4 的事。

**2. 身份**
普通 Agent 拿不到 Rokid 账号，眼镜给的设备 ID 官方明说不能当凭据。所以自建身份：玩家第一次联机时，眼镜本地生成 playerId 和一把密钥，调注册接口换回服务器令牌，之后每个请求带令牌和签名。换设备靠恢复码找回，不承诺「登录即找回」。

**3. 三种多人玩法，三种实现难度**
- **异步共享（先做）**：你把一间房提交共享 → 进审核队列 → 过审后，别人站在同一地点附近能读到它（按约 100 米的粗格子查，不传精确坐标）→ 他在你的房里打任务、留一句题字，你得「回响」。全是普通 HTTPS 请求，玩家打开 Agent 时拉取和上报，没有实时性要求，最好实现。
- **异步协作**：一只大蚀影或一处褪字场所需要多人先后出力——每个人的贡献是服务器上的一条追加记录，服务器汇总结算，谁上线谁接着打。
- **同地回合制（最后做）**：两个人都站在同一地点、都打开 Agent，一个人建会话出一个短码，同伴输码加入；之后一人一回合，每回合把动作发给服务器，服务器按序号定序、结算战斗、把新状态推回来。眼镜开着的时候可以走 WebSocket 长连接（官方 API 有），嫌复杂先用每 2–3 秒轮询也够——回合制不怕这点延迟。有人关掉眼镜，会话不丢，对方界面明示「等对方回来」，不假装实时。

**4. 两条纪律，先说丑话**
- **分工**：你自己的世界（私人房间、背包、经验）本地优先，服务器只做按块同步，冲突时按修订号处理、永不静默覆盖；凡是「大家共用」的东西（共享房、会话、回响货币）一律服务器说了算，眼镜只上报动作、不自报结果。
- **防作弊只能防一半**：看图判定是在眼镜端用宿主大模型做的，照片出于隐私又永不上传，服务器没法复核「他真拍到了吗」。所以共享玩法的奖励要封顶、限频、加审核，设计上就不让作弊能刷出大收益——这条写进数值表，不装作能全防。

网络侧的琐事：眼镜请求只能 HTTPS，上线前域名要向 Rokid 报备白名单；没 Wi-Fi 时流量自动经手机 App 蓝牙转发，玩家无感；服务器挂了或没网，单机玩法照常，联机功能静默缺席（架构里网络层空实现就是为这个留的）。

这套和架构文档 §9 的接口形状是一回事，这里是把它讲到实现层。要的话我把它补进架构文档出 v0.2，和 D1–D5 一起等你点头。

有，而且这正是大表哥用的那条路——大表哥不是什么特殊通道，它就是一个普通 Agent 在直连一台自建服务器。官方的基础网络能力是 Agent 自带的，不依赖任何 tunnel：

**能直连的证据（能力档案 §2.13，官方网络指南）**
- Agent 里可以直接用 `fetch` / `wx.request` 发 HTTPS 请求，用 `WebSocket` / `wx.createSocket` 开 wss 长连接，还有 SSE（`wx.createEventSource`）。地址你自己写，指向你自己的服务器，中间没有任何必经的中转服务。

**直连的三个条件**
1. **只能 HTTPS**（长连接就是 wss），裸 TCP、SMTP 这类协议级直连没有，只有 Web 协议这一套。
2. **域名要报备白名单**：正式提审上架前，请求的所有域名需在开发者后台报备，没报备会被宿主拦（错误码 E6010 就是这个）。
3. **物理链路有两种，代码无感**：眼镜连了 Wi-Fi 就直连出去；没 Wi-Fi 时，只要蓝牙连着手机 App，请求自动经手机转发上网——这是系统级的借道，对代码透明，你写的还是服务器的直达地址，不算应用层 tunnel。

**两个边界，顺带说清**
- **没有局域网直连**：连不上同一 Wi-Fi 下的电脑或 NAS，只能连公网服务器。
- **只在 Agent 打开期间联网**：关掉就断，没有后台常驻、没有服务器推送唤醒——所以多人设计才走「打开时拉取 + 回合制」。另外一个未验证项：WebSocket 长连接能不能稳定穿过手机蓝牙借道，官方只证实了普通请求，之前通道项目就把这条列为待真机探针——MUD 阶段 4 真要上长连接之前，先探针验它，不过回合制用轮询也完全够用。

## Muse — 2026-10-25 21:00

不能，做不了你说的那种**真·实时 AR**。能做的是前台的**采样式伪实时**，差别在这：

**Agent 拿得到的（官方 API 实证）**
- `getUserMedia({video})` 能拿到实时视频流，`MediaRecorder` 能录成 `video/mp4 / webm`，`ImageCapture.grabFrame()/takePhoto()` 能抓帧
- 录/抓的同时能交互：镜腿手势、点头/头稳、ASR、TTS、LLM 都能并行跑
- 权限就是 `CAMERA + RECORD_AUDIO`

**卡死真 AR 的四条**
1. **LLM 没有视频输入** — 只收单张静态图（`image_url`，可 data: URL）。所谓“看懂画面”只能每隔几秒抓一帧 → 送 LLM → 把结果贴回屏幕，不是 30fps 连续理解。
2. **没有空间锚定** — 无 SLAM、无 world anchor、无平面/深度/物体跟踪、无眼动。叠加的标签只能固定在 480×352 单色绿屏幕坐标里，你头一转，标签不会钉在真实物体上。能用的只有头部朝向四元数 + 点头 + 头稳事件。
3. **不能常驻后台** — `getUserMedia` 必须由用户交互、在交互态的前台 Page 里发起，用完必须 stop track；Agent Worker 的 `background` 生命周期保留且无效。关掉 Agent / 息屏就停，做不了行车记录仪式常录。
4. **物理账** — 210 mAh 电池、拍摄指示灯必亮、无任意文件系统可写（长录像存哪儿都是问题）；官方也没公布 AIUI 视频流的最高时长/保证帧率，实际值只能读 `track.getSettings()` 真机测。

眼镜系统自带的录像（最高 3K 30fps）是整机功能，不等于 Agent 能调用它做交互。

我们现有舰队的 SCAN 模式就是上限内的正确形态：看着目标 → 头稳触发抓帧 → LLM 识别 → 屏幕/TTS 反馈 → 手势确认下一步。想要再往前探，我可以做个探针 Agent，专门真机测三件事：持续流能跑多久不掉帧、grabFrame 实际速率、抓帧→LLM 往返延迟。

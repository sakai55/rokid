一句话：**自带 AI 助手是前台管家，LLM 是它背后的大脑，App 里选/下载的“模型”是给管家换大脑、或给眼镜装离线工具包——三者不是三个并列的东西。**

**1. 自带 AI 助手（乐奇 / Hi Rokid 唤醒的那个）**
它是宿主系统常驻程序，不是模型本身。负责：
- 唤醒（“Hi Rokid / 乐奇”、镜腿长按）、收音、显示、播报
- ASR 语音转文字、TTS 文字转语音（11 个固定音色）
- 意图分发：翻译、字幕、会议转写、提词器、慧眼辨识、导航、语音笔记这些自带功能，都是它内置的技能
- 权限、网络、调用哪个模型，也归它管

**2. LLM 是助手背后的推理引擎**
工作流是这样一条链：

> 你说话 → 4 麦阵列收音 → **宿主 ASR** 转文字（+需要时摄像头拍照）→ **LLM** 推理/看图回答 → 流式返回文字 → 眼镜上出卡片 + **TTS** 播报

ASR、TTS、LLM 是三段不同的活：ASR 和 TTS 只是“耳朵/嘴”，LLM 才是理解和生成的那部分。看图问答也是同理——拍照后把图片以 `image_url`（含 data: URL）喂给多模态 LLM，没有单独的 OCR/识图模型在眼镜里跑。

国际版公开报道说，Rokid 已把 Gemini、ChatGPT、DeepSeek、Qwen 整合到统一平台里让用户切换，其架构明确叫 **device-to-cloud**，即端到云切换模型。

**3. App 里“下载/选择模型”到底是什么，要分两种**

- **云端大模型的选择**：这不是把 GPT/Gemini 的权重下载进眼镜。眼镜只有 AR1 + 2GB 内存 + 210mAh，装不下也跑不动那种模型。你在 App 里选它，本质是设置宿主的 `defaultModel` 偏好/路由，推理仍在云端跑，眼镜经 Wi-Fi 或经手机蓝牙代理（HTTPS）把请求发出去、把流式结果收回来。
- **离线资源包的下载**：比如翻译的离线语言包——公开规格说翻译支持 89+ 语言，主要 6 种可离线。这类才是真下载到眼镜 32GB 存储里的小模型/词库，断网能用，但只会干翻译这一件专门的事，不是通用 LLM。

**4. 和我们做的 AIUI Agent 的关系——最关键的一点**
Agent 自己**不带模型**。我们的 .aix 包只有 8–20KB，里面只有 JS/Ink 页面代码。Agent 里调的是宿主 API：

- `LanguageModel.create({model?, ...})`：解析顺序是代码里显式写的 `model` → 宿主 `defaultModel`，不写就用宿主默认那个
- `LanguageModel.availability()` 只回 available/unavailable，**不暴露供应商、模型列表、端点**——这是官方 AIUI 文档核实过的（2026-10-24 能力档案 §2.9）
- 工具调用以 `toolcall` 事件回传给 JS，还得 Agent 自己执行，不是模型直接动手

所以：自带助手和我们的 Agent 用的是**同一套宿主基础设施**（同一个 ASR、同一个 TTS、同一条宿主 LLM 通道），区别只是助手是系统级的、Agent 是跑在上面的小程序。

一个诚实的未知点：App 里给助手切换模型的那个开关，是否同时改掉 Agent 的 `defaultModel`，官方文档没有明说，档案里也没有实证——如果你指的是 App 里某个具体的模型下载页面，把那页截个图给我，我能对着清单逐项给你标出哪个是云端路由、哪个是离线包。

## Muse — 2026-10-25 21:32

眼镜端发送其实都是 POST 出去，**三方案的差别在结果怎么回来**。都写进设计文档了，结论先说：**v1 用方案 A**，因为通道的瓶颈是 Muse 处理那 30–90 秒，运送只差几秒。

**方案 A：POST + 短轮询（推荐）**
`wx.request` 把话 POST 到前门拿到 ticket，然后每 3–5 秒 GET 查一次状态，`done` 就渲染+播报。
最简单最稳：无状态、断线了再查一次就行；普通 HTTPS 请求走手机蓝牙代理已证实没问题；和 Apps Script + Sheet 前门天然兼容；省电。代价只是多等一个轮询周期，几秒钟，无感。

**方案 B：POST + 长轮询**
发送同 A，但 GET 时服务端把请求 hold 住最多约 50 秒（要小于 `wx.request` 默认 60 秒超时），结果一出来立刻返回，没有就空返回、眼镜马上再发下一次。
回单近乎即时、请求数少得多。但服务端得能「挂住」请求——Apps Script 是算完即返回的模型，做不了，前门得迁到能长驻请求的服务。所以它是 A 的体验升级版，等跑通了嫌慢再换，信封协议不用动。

**方案 C：WebSocket 长连接**
眼镜用 `wx.createSocket` 开一条 `wss://` 长连接，发送走连接、结果由服务端真推下来（单向版是 SSE，`wx.createEventSource`，回单场景其实够用）。
延迟最低、多轮对话最自然，是终局形态。但代价全在对面：Apps Script/Sheet 不支持 WS/SSE，必须自建常驻服务（比如 Cloudflare Worker），「不养服务器」的前提就没了一半。还有两个未验证项：WS 升级请求能不能穿过 Hi Rokid 的蓝牙代理（官方只证实普通请求可以）、页面息屏后连接保活怎么样。这两个得先拿探针在真机上验，才能立项。

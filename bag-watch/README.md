注意力外挂系列 D02（DUAL 并行型，本组第二位）。在车站等车、在咖啡馆买东西，主线是等车/买东西，副线是「脚边身后的行李还在吗、走的时候别忘拿」——两件事抢同一双眼睛：一直盯着行李就没法安心等，安心等就容易起身走人时把行李落下。本 Agent 把副线外包出去：看向行李方向停稳后 REG 登记一次，之后每 5 分钟（演示间隔）提醒回看一次；点按或头稳点头确认「还在」，计时重置；一次提醒没确认，下一轮升级为 TTS + 更醒目横幅；再没确认就出「请起身去行李那一格看一眼」的强提醒；想走的时候点「要走了」，进入离开门——转头对准登记朝向停稳、点头/点按 GOT 确认「拿上了」，才放行结束；没过离开门就点结束，只会当场喊停并点名「行李还没确认」，绝不报「可以走了」；结束时给一张小结：回看确认几次、未确认提醒几次、喊停几次、离开门是否通过。

## 解决的问题

在途行李的注意力分叉：行李在脚边身后，眼睛又要顾主线——买咖啡、看时刻表、回消息，注意力一走，行李就从脑子里掉出去了。最危险的不是等的时候，而是起身那一刻：人一起身，注意力就切换到「往哪走」，行李最容易在这个切换点被落下。本 Agent 管两件事：等的时候替你记着抬头看一眼，走的时候在门口拦你一下——拦的不是门，是你脑子里的切换点。

## 注意力外挂设计（DUAL 并行型）

- **副线只是一条登记过的朝向，不是检测到的行李**：REG 登记的只是一个「行李」标签和登记时朝向——没有摄像头、没有麦克风、没有定位、没有步数/移动感知，所以它根本不知道行李是否真的在手，也永远不声称知道。朝向是提醒的锚点，不是行李的位置；「拿上了」是你本人的表态，不是传感器的证明。
- **计时器是守望的全部机制，且只有一条决策路径**：每 5 分钟一格，到时未确认才升级——横幅（无 TTS）→ TTS + 更醒目横幅 → 请起身强提醒。演示计时（TICK）和真实 30 秒轮询走同一条 `_checkDue`，预览和真机不可能在升级行为上各说各话。
- **第一级提醒故意不出声**：只是等着的人不需要每次都被语音打断；声音只花在升级和喊停上——副线如果每次都喊，副线本身就成了打断源。
- **离开门是本 Agent 存在的理由，且无法绕过**：END 不是出口——守望中或离开门里，没过门就点 END 只会喊停计数 +1、横幅 + 一次 TTS，原地不动；只有 LEAVE 开门 → 转头对准登记朝向停稳 → GOT 确认「拿上了」→ 回到守望，END 才真正结束并出小结。没有任何一条路径能在离开门未通过时到达小结，没有任何一条被喊停的状态文案会说「可以走了」。
- **确认是你本人的表态，不是传感器的证明**：点按或头稳点头即代表「我看向行李并确认了」/「我拿上了」；不稳的点头不占 1.2 秒锁。页面、朗读、README 都明说：没有任何传感器能证明行李被看见或在手。
- **纠错便宜，销毁需确认**：小结页返回键回到守望（不删东西，离开门仍通过），确认（点按/点头）才清空本次记录；离开门里返回键取消本次离开（不计喊停——还没走，只是不走了）；没有 DEL 键——清掉横幅却还记着「已提醒」的状态，比开着提醒更会骗人。
- **只记本次等候，关掉即清（诚实边界）**：行李、计数、记录只存会话内存，关掉 Agent 即清——上周的行李朝向对今天没有任何意义，存下来才是误导。
- **它不是防盗/防丢设备（最重要的一条）**：没有行李检测、没有定位、没有步数/移动感知，不能保证行李不丢；它只负责提醒你回看、并在离开时拦你确认一次，拦完之后行李在谁手里、安不安全，全是你自己的事。
- **为什么胸前设备做不了**：提醒必须进视线（低头看胸口设备等于又一次离场）；喊停必须是一眼可读的横幅而不是一句语音（语音说完就没了，横幅留在视线里才拦得住人）；确认要靠点头/点按完成而不离场（摸胸口确认本身就是一次离场）。三条都只有头戴设备成立。

## 与邻近 Agent 的分工

- 注意力系列 `pack-sweep`（C04）：出门前在家装箱清点——逐件确认装进了包；本 Agent 从包已经装好、在途才开始，从不列包里有什么。
- 注意力系列 `last-glance`（C01）：离开一个地方时按区拍照存档、事后焦虑时回放——价值在事后；本 Agent 是事中且预防性的：等的时候守望，走的时候在门口拦截。
- 注意力系列 `play-watch`（D01）：同组模板——同一条计时阶梯、同一条点头纪律、同一条零落盘规则；但它的副线是游乐场活动区，且完全没有离开门。本 Agent 增加离开门与喊停计数，因为「忘了看」和「起身忘拿」是两种不同的失败。

## 功能流程

1. **登记副线（REG / 点按 / 头稳点头）**：看向行李方向停稳后登记，守望开始，下次回看 5 分钟后；演示时行李为标注的示例（黑色背包）。
2. **守望计时（TICK 演示计时）**：守望屏一眼可见行李与下次回看时间；真实设备上 30 秒轮询一次，到时自动提醒。
3. **回看提醒（横幅）**：到时出横幅「看一眼行李」，不出声；GOT 点按或头稳点头确认，计时重置并记一条回看记录；未到提醒时间的提前确认也计入，但标注为「提前回看确认」。
4. **升级提醒（TTS + 更醒目横幅）**：一次提醒没确认，下一格升级为 TTS 报一次「还没确认，请再看一眼行李」，未确认计数 +1。
5. **强提醒（请起身）**：再没确认，升级为「请起身去行李那一格看一眼」，之后每格未确认计数继续走，等级停在最强一级。
6. **离开门（LEAVE → GOT）**：想走时点 LEAVE 进入离开门——转头对准登记朝向停稳，点头/点按 GOT 确认「拿上了」（你的表态，非检测），回到守望，离开门已通过；离开门里返回键取消本次离开（不计喊停）。
7. **喊停（END 未过门）**：守望中或离开门里，没过门就点 END，只会喊停计数 +1、横幅「还没确认！」+ 一次 TTS「行李还没确认，先过离开门」，原地不动，绝不报「可以走了」。
8. **结束与小结（END 已过门）**：小结列出回看确认几次、未确认提醒几次、喊停几次、离开门是否通过、回看记录几条；返回键回到守望（不删东西，离开门仍通过），确认后清空本次记录。
9. **演示（DEMO）**：五段演示——守望登记（示例行李）→ 回看提醒横幅（无 TTS）→ 回看确认 + 离开门打开 → 未过门点 END 被喊停（喊停 1 次）→ GOT 过门 + END 出小结（确认 1 次、未确认 0 次、喊停 1 次、离开门已通过）；已有用户守望或用户离开门时 DEMO 拒绝，绝不覆盖。

## 手势映射

| 手势/按键 | 动作 |
|---|---|
| 点按（Enter） | 待机：登记副线；守望中：确认还在；离开门：确认拿上了；小结页：确认并清空 |
| 双击（Backspace） | 小结页：回到守望；离开门：取消本次离开（不计喊停）；守望中/待机：无动作并说明 |
| 上滑（ArrowUp） | 回看记录下一条 |
| 下滑（ArrowDown） | 回看记录上一条 |
| 头稳 + 点头 | 待机：登记副线；守望中：确认还在；离开门：确认拿上了；小结页：确认并清空；不稳的点头不计入 1.2 秒锁 |
| 屏上按钮 | DEMO 演示 / REG 登记 / TICK 走一格演示计时 / GOT 确认还在或拿上了 / LEAVE 要走了开离开门 / END 结束（未过门只喊停）/ SPEAK 朗读当前状态 / BACK 返回 / NEXT 下一条记录 / PREV 上一条记录 |

## 权限说明

- 不申请任何权限（app.json 的 `permissions` 为 `[]`，静态校验明确断言这一点；空权限已有 shelf-sweep、pack-sweep、play-watch 的先例）。
- 不申请 `CAMERA`（没有任何拍照环节：行李靠看向停稳登记，演示行李是标注的示例）、不申请 `RECORD_AUDIO`（没有任何语音输入：升级提醒与喊停的 TTS 是输出，不是录音）、不申请 `GEOLOCATION`（等候副线不需要定位）。

# 描红系列 PLAN（Rokid AIUI Agent）

> 系列定义（GO 2026-10-29 定，系列旁聊原话钉死，PLAN 内不得改写）：**「描红」为借名——实质偏临摹 / 对形，不是同面叠合描摹。** 壳 = 眼镜画面中央一个范本、边上是步骤，用户照着范本用自己的手（或手里的笔）做到位，主动触发拍照，眼镜拍照给 LLM 看，判定过了才进下一步。一句话：**中央范本 + 边上步骤 + 做一步验一步。**
> 立壳原因：眼镜没有手部追踪、做不了实时纠正；范本浮在眼前，用户自己把手 / 笔伸过去对齐，对齐的过程就是学习。系统不盯过程，只在每步结束时定格验收。

## 0. 平台铁律（全系共用，写进每台 AGENTS.md 与 README）

1. 看手 / 看成果只能靠拍照 → data URL → LLM 图片输入（`ImageCapture.takePhoto` + `blob.arrayBuffer()` + 分块 `btoa`；**禁用 FileReader**，E2005 教训）。是定格判定，不是连续追踪；动态词、手的轨迹、实时纠偏一律不做，必须切段验。
2. LLM 看图会认错：每台判定后必须有用户覆盖口（「算过 / 不算过 / 重拍」三选，点头确认当前高亮项），认不准时 UI 与 TTS 老实说「没看清」，不硬判。判定原文（`encodeError` / LLM 原始返回）留 `lastError` 与日志，不粉饰。
3. 识别只是闭环里一步：单独做「认出这是什么」与慧眼默认能力同本体，出局（冲突对比见 §6）。每台必须有完整场景：学 / 练 → 验收 → 进度落盘下次接着练。
4. 视角铁律（本系列特有）：眼镜相机看用户自己的手是**佩戴者视角**（手背朝相机、左右与旁观者相反）。所有手势类范本（结印、手语）必须按佩戴者视角绘制 / 标注，禁止直接照搬给旁观者看的教材图——这是探针要验的第一件事。
5. 通用规矩：绿色色阶禁纯白（最亮绿 `#7dff9e` 充白位）、裸错误码 `E####`、API 清单纪律（查无即不存在、静态 grep 一票否决）、手势优先按钮最少、README 顶部 Studio 导入块 + 错误码节 + 提审资料节、截图嵌 README、`.aix` 进 `aix/`、提审等 GO 说「真机测试完成了」。

## 2. 共用壳：四部件复用方案

AIUI Agent 之间不能互相调用、也不能共享运行时代码包，所以「复用」= **仓库模板复用**：壳沉淀为仓库 `skills/` 旁的模板目录（建首台时落地 `trace-shell/` 模板 + 版本号），每台建时拷贝当版壳代码进自己工程、README 记壳版本；壳升级只影响新建 / 明示升级的台，不回改已建台（同错误码表的治理法）。

| 部件 | 文件（每台工程内） | 接口（全系统一） | 各台只换什么 |
|---|---|---|---|
| ① 范本显示 `ModelView` | `pages` 共用布局：中央范本区（约 300×300）+ 右侧步骤栏 | 输入 `{steps[], current}`；当前步最亮绿、已过步中绿、未到步暗绿；范本形态三类：笔画路径（毛笔）、线条手势图（结印 / 手语）、图示步骤图（折纸等） | 范本数据与画法 |
| ② 步骤条 `StepRail` | 边上步骤栏组件 | 步骤数组 `{id, title, tip}`；TTS 同步念当前步要点（可关）；滑动切步只许回看，不许跳过未验步 | 步骤文案 |
| ③ 拍照验收 `PhotoJudge` | `photo-judge.js` | 触发：点头 / 点按（用户主动）；拍照模式按台声明（手 / 纸面用 `default`，细节用 `telephoto`）；提示词合同固定四段：对照范本描述 → 只查清单内粗项 → 输出结构化判定 `{pass, issues[], confidence}` → 看不清就说看不清；判定后用户覆盖口三选一，覆盖记录落盘（探针与正式版都靠它攒真值） | 每台的「粗查清单」与范本描述文本 |
| ④ 进度存储 `Progress` | `progress.js` | 统一键 `trace.<slug>.v1`：`{done:{itemId:{count,lastAt,overrides}}, today, lastItem}`；写入失败静默 + 裸码上报，不许因存档失败中断练习（错误处理不制造新错误） | item 集 |

验收口径（精品验收 skill 适用）：声称的闭环每一步须在建成文件里找到对应调用；范本 / 内容集须可数；跨会话须找到持久化代码。

## 3. 首批三台 · 立项三关自查

### TR01 毛笔字描红 `trace-brush`（候选编号，下同）

- **场景关**：书法初学者晚上在书桌前铺纸研墨，打开它一笔一笔练完今天的一个字，写完当场知道差在哪、下次接着练。✅
- **闭环关**：选字 / 今日一字 → 学字（逐笔范字 + 要点 TTS）→ 真纸真笔写 → 低头拍照验字 → 一句人话点评 + 用户可覆盖「这字算过」→ 次数与已练集落盘 → 下次续练 / 复习。✅
- **厚度关**：内容集 20 字（分笔数据可数，来源见 §5）+ 多步流程（逐笔学 → 整字验）+ 跨会话记忆，三样齐。✅
- **红线**：判定只对用户自己写的字；只查粗项（少笔多笔、结构重心、最明显的一两处），不装专业评分；不拍他人正脸；无医疗 / 康复声明。

### TR02 结印描红 `trace-seals`（探针先行，§4）

- **场景关**：忍者手印爱好者在家对着眼镜把一条手印序列从头结到尾，描红档慢学、竞速档比谁结得快而准。✅
- **闭环关**：选序列 → 逐印范本 + 步骤进度 → 摆好点头拍照 → 判定过 / 不过 → 序列结算（描红档：完成度；竞速档：总时 + 错印数）→ 成绩与已学序列落盘。✅（竞速档收录范围由探针结果定，见 §4）
- **厚度关**：内容集 12 基本印 + 原创序列库（原创命名，提审版只用泛称「忍者手印」，不用「火影」与原作忍术名）+ 多步流程 + 跨会话成绩。✅
- **红线**：手指交缠、正面只差一根手指的印可能认不准——认不准的印只进不计分描红档或不收，绝不硬塞竞速档。
- **连续多图（GO 2026-10-29 追加指令）**：结印范本不用单张静态图——每个印给**连续多图**：3 帧成印过程图（①起手双手分开位 ②交指中段 ③成印定格），佩戴者视角线条图、绿色色阶。显示：中央大图逐帧推进（描红档自动慢放 + 可滑动回看，竞速档只闪定格帧），画面下方一条缩略帧带显示走到第几帧；整条序列另有一张连续图带预览（一排小图看全程顺序）。拍照验收仍只在第 ③ 帧定格做——多图是教「怎么结」，判定还是定格判定，不暗示连续追踪。探针同步执行：探针里每个印同样出 3 帧连续图，GO 照帧摆到定格再拍。

### TR03 手语描红 `trace-sign`（体系已定 JSL、全日语 UI，探针先行，§4/§8）

- **场景关**：想学手语的人在家对着眼镜把今天的几个手势摆对，攒下已学词集，隔天抽查复习。✅
- **闭环关**：学（范本 + 要点）→ 摆 → 点头拍照 → 判定像不像、差在哪根手指 → 过了进下一个 → 已学集落盘 → 复习抽查模式（只给文字不给范本，反向考）。✅
- **厚度关**：静态手势内容集（指文字 + 数字 + 静态日常词，数量由探针命中率定）+ 多步流程 + 跨会话 + 抽查模式。✅
- **红线（定位钉死）**：这是学 / 练手语的 Agent，**不是手语翻译**；文案不许暗示能翻译、能与聋人实时对话（实时翻译靠连续追踪，眼镜没有）。只收一张照片能定格判断的静态手势；需要动起来才成立的词不收，清单里逐个注明不收原因。

## 4. 识别可行性试验（结印 + 手语，共用探针规格）

探针是独立最小 Agent，不占正式编号、不上清单、不挂徽章：slug `trace-probe-seals` / `trace-probe-sign`，分支照旧 `agent-<slug>`，验完保留在仓里作证据（不删）。

**探针干什么（3 页）**：
1. 说明页：一轮怎么跑、摆位要求（双手举到眼前约 30–40cm、光线、背景尽量素）、视角声明。
2. 轮测页：按固定顺序逐个提示目标（结印 12 印 / 手语首批候选静态手势），显示范本（佩戴者视角线条图 + 要点文字；结印为连续多图 3 帧，见 TR02 条）；GO 摆好后点头拍照；LLM 只回答一件事——「这张照片里摆的是哪个（从全集名单里选）+ 像不像目标 + 哪根手指对不上」；随后 GO 点选真值确认（判定对 / 判定错，我摆的就是目标 / 我故意摆错）——真值由 GO 的确认定，不由 LLM 定。
3. 结果页：逐项表（目标 / LLM 认成什么 / 对错 / GO 备注）分页可看，汇总认对数；结果同时落盘 `trace.probe.<kind>.v1`，GO 回传方式 = 结果页截图 + 口述汇总数（若日志通道已配钥，可另走日志回传，没配则静默不用）。

**GO 真机配合**：每探针摆一轮即可（结印 12 印 ×1；手语候选集 ×1），全程约 10 分钟；同一光线、同一背景；每个目标只拍一张（拍糊可重拍一次，记为重拍）。

**结果怎么决定玩法（事先定死，不事后挪标准）**：
- 单项认对 → 进正式版计分 / 竞速范围；
- 认错（认成别的项）→ 只进不计分练习档，且在练习档里该项范本旁标注易混对象；
- 「看不清 / 没判」→ 复测一次，仍不行则不收；
- 全集认对率 <50% → 该 Agent 玩法降级为「自评描红」（LLM 只给差异提示、过与不过由用户自定），并在立项页如实改判，不硬做判定档。

## 5. TR01 毛笔字 · 设计页数与字库来源方案

**页数：7 页**（按 `app.json` / `pages/` 实数口径，状态不算页）

| # | 页 | 干什么 |
|---|---|---|
| 1 | 今日页 | 今日一字、上次练到哪、继续 / 换字入口 |
| 2 | 字库页 | 20 字总表（每字标笔画数、练过次数），滑动选字 |
| 3 | 学字页（描红主页） | 中央范字：当前笔最亮绿、已学笔中绿、未学笔暗绿；右侧笔顺步骤 + 本笔要点，TTS 同步念要点；逐笔推进 |
| 4 | 字义 / 笔法页 | 该字读音、字义一句、本字重心提示（如左右结构看让侧）——内容页，与学字页画法 / 接线不同，不算状态页 |
| 5 | 验收页 | 提示低头对准自己写的字 → 拍照 → LLM 对照范字粗查三项：少笔多笔、结构重心偏没偏、最明显的 1–2 处 |
| 6 | 点评页 | 一句人话点评 + 三项结果 + 覆盖口（算过 / 再写一张 / 跳过），覆盖落盘 |
| 7 | 进度页 | 已练字集、每字次数、连续练习天数；复习入口（随机抽一字只给读音不给范字，写完再验） |

**字库来源方案（双源：机器分笔数据 + 国家规范校对，缺一不收）**

- **分笔数据（机器可读，决定能不能画逐笔范字）**：`hanzi-writer-data`（Make Me a Hanzi 项目）——每字一个 JSON，`strokes[]` 为逐笔 SVG 路径（数组顺序即笔顺）、`medians[]` 为逐笔中线点列，全集 9000+ 字。该数据由 Arphic（文鼎）字体提取，按 **Arphic Public License** 再分发，商用提审可走通；工程内须带许可证文本与出处标注。✅
- **笔顺校对（决定顺序对不对）**：《通用规范汉字笔顺规范》GF0023-2020（教育部、国家语委 2020-11-23 发布，2021-03-01 实施，替代 1997 年版）——覆盖《通用规范汉字表》8105 字，给出逐笔跟随式与序号式笔顺。✅
- **收字规则**：候选字必须 ① 在 hanzi-writer-data 里有完整分笔 JSON；② 笔画数与笔顺经 GF0023-2020 核对一致（不一致以 GF 为准改序，改不了序的弃）；③ 简繁同形（避开 Arphic 台湾字形与简体字形分歧，如「马 / 馬」类不收）；④ 每笔要有可写的一句要点（起笔 / 行笔 / 收笔，属本系列自撰练习提示，不冒充书法评分标准）。四条缺一不收，宁可少于 20，不凑数。
- **明确否决的来源**：台湾教育部「国字标准字体笔顺学习网」——其笔顺动画 / 全笔顺提示为 CC BY-NC-ND 3.0 TW（非商业 + 禁改作），与商店提审冲突，只作人工参考、不取数据。
- **首批 20 字候选（全简繁同形、由易到难排）**：永（8) 人（2) 大（3) 天（4) 上（3) 下（3) 山（3) 川（3) 水（4) 火（4) 木（4) 日（4) 月（4) 田（5) 口（3) 中（4) 心（4) 正（5) 生（5) 白（5)——括号为待 GF0023-2020 逐字复核的笔画数，复核不过的按规则换字并在本表回填。选字逻辑：永含永字八法基本笔法，人 / 大 / 天一组看撇捺与重心，山川水火木为独体象形，日月田口中为框形结构，心正生白收尾看卧钩与重心。

## 6. 对比冲突（全系 8 台 vs 默认能力基线，rokid-conflict-audit v1.0.1 口径）

基线七项：①实时翻译 ②实时字幕 ③会议转写 + 摘要（含语音笔记）④提词器 ⑤慧眼辨识 / AI 视觉问答 ⑥AR 导航 ⑦个人助理问答 / 通知 / 拍照录影。

| 台 | 本体一句话 | 最接近的基线 | 判定 | 理由 |
|---|---|---|---|---|
| TR01 毛笔字 | 逐笔教写 + 拍照验字 + 进度 | ⑤慧眼 | **待测试** | 识别只是闭环一步；默认能力没有笔顺教学、没有对自写字的结构粗查点评、没有跨会话字集进度。问慧眼「我这字写得怎么样」得不到逐笔课程与落盘进度 |
| TR02 结印 | 序列描红 + 逐印验收 + 竞速结算 | ⑤慧眼 | **待测试** | 本体是玩法闭环（序列 / 计时 / 计错 / 成绩），慧眼无序列教学与结算 |
| TR03 手语 | 静态手势描红练习 + 抽查复习 | ①实时翻译（字面最像） | **待测试（重点声明）** | 本体是「学」，不是「译」：不做连续手语理解、不产出翻译结果。风险点只在文案——README 与 UI 必须明示非翻译，提审资料里先行声明，避免审核按翻译类目误判 |
| TR04 折纸 | 分步折形描红 + 每步拍照验形 | ⑤慧眼 | **待测试** | 验形是闭环一步；本体是分步教程 + 形状进度，慧眼无此课程结构 |
| TR05 绳结 | 绳结分步描红 + 每步验结形 | ⑤慧眼 | **待测试** | 同上；结形只查粗项（圈数、穿向、收尾位置） |
| TR06 简笔画 | 线条简笔画描红 + 拍照对形 | ⑤慧眼 | **待测试** | 本体是分步学画 + 进度；与 TR01 的差别在对象（图形线条非文字笔顺）与内容集，场景不同不合并 |

## 8. 手语体系（GO 2026-10-29 已定：日本手语 JSL）

> 决策已落：TR03 用日本手语（JSL），UI 全日语；CSL 留作将来独立编号姊妹台，不在本台加开关。以下建议原文保留作决策依据。
> **JSL 探针候选集（首轮 22 项，定版）**：指文字元音 あ・い・う・え・お（5)；各行あ段 か・さ・た・な・は・ま・や・ら・わ（9)；混淆组补项 に（与 な・は 同手形异方向）、て・ほ（同为平手、掌心相反）（3)；数字 1・2・3・4・5（5)。合计 22 项。建探针时逐项以《わたしたちの手話》手形描述核对、自绘佩戴者视角线条图；靠动作区分的浊音 / 半浊音 / 促音 / 拗音 / 长音一律不入候选，正式版清单里逐类注明不收原因。首轮只测指文字 + 数字，静态日常词等指文字组结果出来后另出候选表。

**建议：首版用日本手语（JSL）。** 理由：
1. **使用地决定手语**：手语是地方语言，不存在「通用手语」。GO 的日常生活与本系列真机使用场景在日本，学会了能当面用的只有 JSL；学 CSL 在日本没有练习对象，闭环的最后一环（学以致用）落空。
2. **静态集边界清楚**：JSL 指文字为 45 个基本手形 + 4 类附加标记，而附加标记全靠动作（浊音横移、半浊音上移、促音 / 拗音回收、长音下滑）——正好整类排除，与本系列「只收静态」规则天然对齐；剩下的静态手形里靠方向 / 掌心朝向区分的（如 な / に / は 同手形异方向）恰是探针最该测的混淆组。
3. **权威源可得且可核**：全日本聋哑联盟《わたしたちの手話》系列与学习辞典为标准源，范本线条图可按其手形描述自绘（不抄图），GO 在日本可直接购得纸本核对。
4. **与既有 JP 线协同**：UI 可全日语、归入日本在地场景叙事，提审故事完整。

**选中国手语（CSL）的理由（同样成立，看 GO 的用途）**：《汉语手指字母方案》GF0021-2019（教育部 / 国家语委 / 中国残联）为国家规范，30 个指式代表 26 字母 + zh/ch/sh 等双字母；《国家通用手语常用词表》（2018 实施）与词典收词 8214 个，权威源齐整；GO 母语为中文，指文字与拼音直连、内容自撰与自核成本最低；若这台的首要用途是回中国使用 / 教孩子，CSL 完胜。

**分界线一句话**：在日本生活里用 → JSL；回中国语境用 → CSL。两套指文字完全不同、绝不混编；选定后探针候选集按该体系出（JSL：指文字静态子集 + 数字；CSL：手指字母 + 数字），另一套留作将来独立编号的姊妹台、不在本台内加开关。

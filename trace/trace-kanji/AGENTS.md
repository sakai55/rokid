# Trace Kanji — Agent Notes

描紅シリーズの漢字版（TR01 trace-brush の姉妹台、番号なし）。殻は描紅殻 v1（ModelView 筆画形態 / StepRail / PhotoJudge / Progress）、描画と注釈系は TR01 v1.3.6 の凍結仕様をそのまま使う。仮名版 trace-kana の筆形（中心線＋実測幅）は輪郭の凹凸が基準に達せず GO の指示で中止となり、本台は TR01 と同じ真輪郭データに戻した（kana は v1.0.1 のまま保存、二度と触らない）。

## Design contract

- シーン：日本語初学者が机に向かい、今日の漢字を一字、範字を一画ずつ見て紙に筆（またはペン）で書き、書いた直後に粗いチェックで違いを知り、次回は続きから。
- 七ページの閉ループ：今日（今日の漢字＋進捗の要約）→ 一覧（30 字・読み・画数・練習回数）→ 学ぶ（範字全面：分筆輪郭を空心で描く——TR01 と同一。全画・全状態で統一の低輝度、高輝度は筆順の弧と番号だけ。弧は書き始めの位置で中心線の開始区間に平行、番号は弧の尾＝書き始めの外側、矢印は運筆方向。画の位置はそのつど保存し、再入で復元）→ 読み方と書き方（読み／意味／構成／重心の目安／画の流れ）→ 写真チェック（下を向いて自分の書いた字を撮り、LLM が粗い三点だけ）→ 講評（三点＋一言、本人の「できた」判定が優先し記録）→ 進捗（練習済みの字／字ごとの回数／練習日数＋復習テスト：読みだけ見せて範字なし）。
- チェックの口径は固定：粗い三点だけ（画の過不足、重心、最も目立つ 1〜2 か所）。点数は付けない。見えなければ正直に「見えない」と言い（CLEAR: NO → 撮り直し）、「できた」は本人の判定が優先（上書き回数を別に記録）。チェックしていない字を「できた」にはできない。
- 判定対象は利用者自身が書いた字だけ。他人の顔は撮らない（チェックページに明示）。医療・リハビリ等の主張なし。
- 進捗の保存キー `trace.trace-kanji.v1`、ページ間の字の受け渡し `trace.kanji.tmp`（受け渡し用、永続ではない）、画の位置 `trace.kanji.learn`（復元用）。
- 手勢の対応：うなずき＝フォーカスの実行（チェックページでは撮影）、タップ＝確定（Enter）、上下スワイプ＝フォーカス移動／字の選択、二本指は戻る（Backspace、一覧ページで接続済み）。

## 字書とデータ出典

- 30 字（常用の小セット、GO 2026-11-01 決定）：一 二 三 四 五 六 七 八 九 十 人 山 川 田 日 月 火 水 木 生 土 大 小 中 上 下 左 右 本 年。全 105 画。
- データ `chars.js`：分筆の輪郭・中心線は hanzi-writer-data（Make Me a Hanzi、Arphic 由来、Arphic Public License、全文 `LICENSE-data.txt`）——TR01 と同じ真輪郭。座標系も TR01 と同一（1024 フレーム、y 上向き）。
- 筆順は KanjiVG（CC BY-SA 3.0）と全字照合（画数一致＋各画の開始位置の照合）。日中の順が違う三字は画ごと入れ替えて日本式にした：**右（1・2画）、田（3・4画）、生（3・4画）**。
- **金は不収録**：8 画の密集字で、凍結した注釈幾何では第 5 画に弧が置けず QC ゲート C1（被覆）が FAIL したため、画数の少ない生に差し替えた。注釈系を解凍しない限り金は戻さない。
- 読み・意味・構成・重心・画の種類・各画の要点は本シリーズ自作（日本語）。要点は粗い練習ヒントで、書道の専門的な評価基準ではない（読み方ページに明示）。
- 画面消灯の境界：プラットフォームに常時点灯／wake lock の API はない（TR01 で全量確認済み）。緩和＝画の位置の保存（キー `trace.kanji.learn`）で再入時に現在画へ復元。README の「プラットフォームの境界」に記載。

## Permissions

`CAMERA`（チェック撮影）のみ。app.json と一致。TTS に独立した権限はない。

## Validation

- Static：JSON 構文、全スクリプトの構文チェック、禁止 API の grep 0 件、緑色階のみ（純白なし）、30 字の画数アサーション（KanjiVG 照合済み）。
- QC ゲート：`qc/check-geometry.js`（TR01 v2 の継承）。**幾何を変えたら必ず再実行：FAIL はパック／提出禁止。WARN リストが基線と変わったら、変わった字の学ぶページを撮影して拡大回読するまで未完。**
- 基線（v1.0.0、2026-11-01）：**QC PASS**——弧 105（平行 94／受け 11＝10.5%）、最小の弧–輪郭距離 6.51px、最小の番号間隔 30.3px、WARN 65 件（全件が既知の妥協クラス）。金の FAIL 2 件（C1 第 5 画に弧なし、C5 第 4 画の弧 11.9px）は字の差し替えで解消した経緯を上に記録。
- Device stage (pending)：実機で画ごとの描画方向、TTS の要点読み上げ、下向き撮影の粗チェックと本人判定の記録を確認。提出は GO が「真机测试完成了」と言うまでしない。

## v1.1.0 の設計（GO 2026-11-03 の四点指示で改版）
- **入口＝選字ページ**：旧「今日」ページは廃止。入口で即、練習の列（PROG.queue、字の配列）をスワイプで送って選ぶ。フォーカス列＝列の字（主）＋末尾 4 項目（読み方／講評／一覧／進捗）。TMP には表示中の字が入り、読み方ページはそれを開く。
- **うなずきの意味はページ固定**：学ぶページだけ「この字を終える」。終了時は judge.js の finishChar が回数+1・練習日・最終字を記録し requeue する。チェック側（講評の「できた」）も同じ finishChar を使うが、二重計数を TMP.counted で防ぐ（先に数えた側が勝つ）。学ぶの「戻る BACK」は記録しない中断。
- **記憶曲線のはしご**：QUEUE_LADDER = [3, 5, 9, 16, 24, 9999]（練習回数を数えた後の回数で引く：n 回目→はしご[n-1] 字後ろ、列が短ければ最後尾）。「練習するほど遠くへ」が仕様。変えるときは GO の指示で。
- **TTS の言語**：speak() は発話に必ず lang='ja-JP' を付ける。付けないとホストロケール（中国語等）で日本語文が読まれ中日混交になる。艦隊の他台にも同じ作りがあれば横展開候補。
- **読み方ページの大字**：<text> はホストフォント描画（中国語字形になり得る）ため廃止し、judge.js の drawGlyph で分筆輪郭を Canvas に塗る。Canvas の教訓二つ：①Ink のレイアウトでは <canvas> に CSS の width/height が必須（属性だけでは潰れる）；②描画はレイアウト直後に失われることがあるため、背景を塗り直してから描く遅延再描画（80ms/450ms、学ぶページと同方式）を入れる。重ね描きの濃化は背景リセットで防ぐ。
- **収録順＝書道入門の進み順**：chars.js の並び自体が進み順（画数少→多、同画数は横画→縦画→払い→組み立て）。列の初期順・一覧の並びはこの順に従う。字の追加時は画数と構成で挿入位置を決める。
- **字形の出典境界（正直条項）**：骨格は KanjiVG と全字一致（監査：~/workspace/rokid/kanji-audit/、中心線の全長照合＋重ね描き目視）。輪郭の比率・様式は出典フォント由来で、日本の教科書体と細部が異なり得る。日本語フォント由来の分筆輪郭データセットは存在しない（KanjiVG は中心線のみ）ため、これ以上の日本字形化はデータ側の新規構築が要る。README の字書節に利用者向けの注記あり。
- 学ぶページの def タイトル誤記（Trace Kana）は v1.0.0 の混入——ページを他台から複製したら def タイトルとヘッダ注釈を必ず自台に直す（今回の検出経緯：GO の「中日混交」指摘からの全面点検）。

## v1.2.0 の設計（GO 2026-11-04「説明は要らない、平鋪＋拡大で」）
- 選字ページはグリッド：30 字をキュー順に平鋪（6 列×5 行＋末尾タイル 4 つ）、セル固定 71×44px、通常 24px／選択中だけ 38px＋明枠＋濃背景。説明文は置かない。情報はステータス 1 行だけ（読み・画数・回数・位置）。セル幅の教訓：Ink のボックスでは border が幅に乗る——6 列に収める幅計算は border と gap を込めること（73px では 5 列に落ちて溢れた）。

# Play Watch（游乐场副线）

**Studio 导入地址**（复制到 Global AIUI Studio 的 Import Project 输入框）：


注意力外挂系列 DU01（DUAL 并行型，本组第一位）。带孩子去游乐场，家长在长椅上歇会儿，主线是休息，副线是「孩子还在活动区吗」——两个都想要的结果是两边都顾不好：要么一直抬头盯着没法歇，要么歇着歇着就忘了抬头。本 Agent 把副线外包出去：看向活动区停稳后 REG 登记一次，之后每 5 分钟（演示间隔）提醒回看一次；点按或头稳点头确认「看到了」，计时重置；一次提醒没确认，下一轮升级为 TTS + 更醒目横幅；再没确认就出「请起身去活动区看一眼」的强提醒；结束时给一张小结：回看确认几次、未确认提醒几次。

## 解决的问题

游乐场里的注意力分叉：休息需要放空，监护需要抬头，两件事抢同一双眼睛。家长的解法通常是「心里记着过一会儿看一眼」，可「过一会儿」是最容易被聊天、手机、打盹吃掉的东西——不是不负责，是人脑的定时器本来就不可靠。本 Agent 把这个定时器外包：它不替你看孩子，它只负责在时间到的时候叫你抬头，确认了就重新计时，没确认就越叫越急，直到你起身。

## 注意力外挂设计（DUAL 并行型）

- **副线只是一条登记过的朝向，不是追踪**：REG 登记的只是一个「活动区」标签和登记时朝向——没有摄像头、没有麦克风、没有定位、没有人体识别，所以它根本不知道孩子在哪，也永远不声称知道。朝向是提醒的锚点，不是孩子的位置。
- **计时器是全部机制，且只有一条决策路径**：每 5 分钟一格，到时未确认才升级——横幅（无 TTS）→ TTS + 更醒目横幅 → 请起身强提醒。演示计时（TICK）和真实 30 秒轮询走同一条 `_checkDue`，预览和真机不可能在升级行为上各说各话。
- **第一级提醒故意不出声**：只是歇着的家长不需要每次都被语音打断；声音只花在升级上——副线如果每次都喊，副线本身就成了打断源。
- **确认是你本人的表态，不是传感器的证明**：点按或头稳点头即代表「我看向活动区并确认了」；不稳的点头不占 1.2 秒锁。页面、朗读、README 都明说：没有任何传感器能证明孩子被看见了。
- **纠错便宜，销毁需确认**：小结页返回键回到守望（不删东西），确认（点按/点头）才清空本次记录；没有 DEL 键——清掉横幅却还记着「已提醒」的状态，比开着提醒更会骗人。
- **只记本次游玩，关掉即清（诚实边界）**：区域、计数、记录只存会话内存，关掉 Agent 即清——上周的活动区朝向对今天没有任何意义，存下来才是误导。
- **它不是监护或安防设备（最重要的一条）**：没有持续追踪、没有人脸/人体识别、不能保证孩子安全，孩子仍需家长视线监护。本 Agent 只负责提醒你抬头，抬头之后看见什么、判断什么，全是家长自己的事。
- **为什么胸前设备做不了**：提醒必须进视线（低头看胸口设备等于又一次离场）；升级提醒要分级亮屏而不是一律出声（胸口设备只能出声，等于把「轻提醒」和「强提醒」压成同一种打断）；确认要靠点头/点按完成而不离场（摸胸口确认本身就是一次离场）。三条都只有头戴设备成立。

## 与邻近 Agent 的分工

- 指向性系列 `cry-watch`：室内婴儿房守听——听的是另一个房间的哭声；本 Agent 什么都不听，它是户外的定时回看提醒。
- 指向性系列 `baby-care-hands`：抱娃时的喂养问答——主线就是娃本身；本 Agent 的几何正好相反：娃在远处的活动区，主线是休息。
- 注意力系列 `door-watch`（WA05）：也是「做别的事时替你守着」，但它守的是门铃/敲门声，需要麦克风；本 Agent 完全没有麦克风，唯一的输入就是家长自己的确认。

## 功能流程

1. **登记副线（REG / 点按 / 头稳点头）**：看向孩子活动区停稳后登记，守望开始，下次回看 5 分钟后；演示时区域为标注的示例（滑梯区 · 红外套）。
2. **守望计时（TICK 演示计时）**：守望屏一眼可见区域与下次回看时间；真实设备上 30 秒轮询一次，到时自动提醒。
3. **回看提醒（横幅）**：到时出横幅「看一眼活动区」，不出声；SEEN 点按或头稳点头确认，计时重置并记一条回看记录；未到提醒时间的提前确认也计入，但标注为「提前回看确认」。
4. **升级提醒（TTS + 更醒目横幅）**：一次提醒没确认，下一格升级为 TTS 报一次「还没确认，请再看一眼活动区」，未确认计数 +1。
5. **强提醒（请起身）**：再没确认，升级为「请起身去活动区看一眼」，之后每格未确认计数继续走，等级停在最强一级。
6. **结束与小结（END）**：小结列出回看确认几次、未确认提醒几次、回看记录几条；返回键回到守望（不删东西），确认后清空本次记录。
7. **演示（DEMO）**：四段演示——守望登记（示例区域）→ 回看提醒横幅（无 TTS）→ 升级提醒（先有一次确认、再有一次未确认，TTS 一次）→ 本次游玩小结（确认 1 次、未确认 1 次）；已有用户守望时 DEMO 拒绝，绝不覆盖。

## 手势映射

| 手势/按键 | 动作 |
|---|---|
| 点按（Enter） | 待机：登记副线；守望中：确认看到了；小结页：确认并清空 |
| 双击（Backspace） | 小结页：回到守望；守望中：无动作并说明（END 结束守望，SEEN 确认回看）；待机：无动作并说明 |
| 上滑（ArrowUp） | 回看记录下一条 |
| 下滑（ArrowDown） | 回看记录上一条 |
| 头稳 + 点头 | 待机：登记副线；守望中：确认看到了；小结页：确认并清空；不稳的点头不计入 1.2 秒锁 |
| 屏上按钮 | DEMO 演示 / REG 登记 / TICK 走一格演示计时 / SEEN 确认看到了 / END 结束出小结 / SPEAK 朗读当前状态 / BACK 返回 / NEXT 下一条记录 / PREV 上一条记录 |

## 权限说明

- 不申请任何权限（app.json 的 `permissions` 为 `[]`，静态校验明确断言这一点；空权限已有 shelf-sweep、pack-sweep 的先例）。
- 不申请 `CAMERA`（没有任何拍照环节：活动区靠看向停稳登记，演示区域是标注的示例）、不申请 `RECORD_AUDIO`（没有任何语音输入：升级提醒的 TTS 是输出，不是录音）、不申请 `GEOLOCATION`（游乐场副线不需要定位）。

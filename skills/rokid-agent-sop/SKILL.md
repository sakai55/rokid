# Rokid Agent Production SOP
中文 | [English](SKILL.en.md) | [日本語](SKILL.ja.md)

One agent = one complete scenario (see the governing rule below — it overrides the older "one life problem" framing). Walk all 9 steps; an agent is not done until step 8 is registered.

## Governing rule — one complete scenario per agent (GO, 2026-10-26)

Set after Rokid's official dev team reviewed the repo and the full overseas Agent Store catalog (~32 listings) was analysed. **Build only "one complete scenario per agent" — never "one feature point per agent".** Official verdict on the old fleet's shape: a feature that small basically cannot pass review, one small point per agent likely passes zero, thin scenarios risk post-listing system bans and user complaints. The store's survivors confirm the bar: complete games with a full play loop, collections under one hub (the store's #2 by usage is a mini-games collection), daily-decision scenarios (what to eat / wear / train today), data-backed services, and content sets — never a single action.

A concept must pass ALL THREE GATES before step 1 design work starts; failing any gate kills the concept on the spot (do not "build it first and see"):

1. **Scenario gate.** One sentence names who opens it, at what moment, to accomplish what — a moment and a task, not an action or a feature. If the scenario cannot be stated, do not build it.
2. **Loop gate.** A full loop: entry → process → result/settlement, repeatable across uses. Single-action, single-page, single-prompt agents fail. Games are the one relaxation (store-proven): a single mechanic is allowed ONLY with a complete play loop (start, win/lose, score).
3. **Thickness gate.** At least two of: real data source, a content set, a multi-step flow, cross-session memory, a collection hub. Same-body-as-a-built-in fails outright (conflict-audit tier 1 — do not regroup, do not submit).

Execution rules:

- **Existing fleet (170+ thin agents).** Never submit them one by one; never delete them. Regroup by scenario — merge the single-point agents of one scenario into one scenario agent; whatever cannot be merged stays archived in the repo.
- **Submission order.** First submission is a gate-passing sample only: (1) the head-games collection hub — ONE monolithic agent containing all the games (agents cannot invoke each other, so a hub is a single agent with the games inside, NOT a router); (2) dabiaoge. Nothing else goes to review until a sample has passed and the real bar is known.
- **Volume production — superseded 2026-10-26 22:49 by the unified boutique line.** The three old daily batch crons (curb-cut / JP-KR / head-games, 3/day each) are CANCELLED. In their place runs ONE cron, `rokid-boutique-daily-10`, delivering only to the side chat 「做的就是精品」: 10 agents/day drawn from five directions — curb-cut (CC), directional, attention, games (GA), JP/KR localization — of the 10, exactly 5 are Japan-locality multi-combinations — JP locale as the scene (JP number, `japan/`, Japanese UI) combined with at least 2 of curb-cut / directional / attention / games, never Japan-locality alone or with a single direction — and the other 5 are free single-direction or 2+ combinations. Combinations must be scenario-native, never a拼盘 of two features. The former `rokid-agent-list-sync` cron (root-README agent list, every 6h) is also cancelled: the boutique run updates the root README list itself, once, after the day's batch is pushed — the SOP step-8 note below and the frozen-badge/legend/retired-slug rules in MEMORY apply to that closing step. Every concept must pass the three gates first; a concept that fails is thickened or dropped with the verdict reported, and the line never lowers the bar to hit the count (shortfall is reported with per-concept verdicts). Framing (GO, 2026-10-26 22:50): the existing 177 agents are an EXPLORATION fleet that probed possibilities and capability boundaries — the boutique line converges on top of it, reusing its verified mechanisms and lessons, and never reproduces its thin one-feature-per-agent shape. The head-games collection hub (`head-games-hub`, GA27–GA40 reserved mechanisms) remains a submission sample as above; the boutique line does not consume those reserved GA numbers for standalone games without GO's instruction.
- **Device-test gate unchanged.** Submission still happens only after GO's real-device testing is complete and GO says 「真机测试完成了」 (step 9).

## Capability red lines (official-source verified, 2026-10-24)

Full registry: `docs/CAPABILITIES.md` in this repo (atomic capability registry; cite entries as C####). Never design beyond these:

- **No eye tracking.** "Gaze" = camera field centre + head orientation (`AbsoluteOrientationSensor`), head-steady confirm via `onOrientationStabilityChange`, nod confirm via `onHeadGesture('nod')`.
- **No OCR API.** Reading text = camera photo + LLM image input. Photo modes via `ImageCapture.takePhoto`: `telephoto` (distant small text, 2016×1512), `wide` (barcode/large field, 2016×2688), `default` (3024×4032). Barcodes: native `BarcodeDetector`.
- **Microphone modes** only via the AIUI microphone API: `wearer` (default) / `far-field` / `near-field` / `omnidirectional`, plus `system-audio`. The wx recorder cannot select a mode.
- **Permissions**: exactly seven names exist, case-sensitive (`1-framework/open-agent-format/app-json.md`): `GEOLOCATION`, `CAMERA`, `RECORD_AUDIO` for device capabilities, plus `READ_MEDIA_IMAGES`, `CREATE_MEDIA_IMAGES`, `READ_MEDIA_AUDIO`, `CREATE_MEDIA_AUDIO` for system media-library access. Unrecognized strings grant nothing; a declaration is not a system grant — refusals and unavailability must be handled at the call site. ASR has no separate permission (the old `SPEECH_RECOGNITION` permission was removed in Ink 0.19).
- **Display**: monochrome green, design to the 480×352 runtime canvas.
- **LLM**: host-managed `LanguageModel` streaming only; tool calls arrive as `toolcall` events and are not auto-executed. **TTS**: 11 fixed voices; the `lang` attribute does not take effect.
- **Network**: HTTPS only, domains must be on the filed allowlist; no LAN direct connections. Network may be proxied via the phone app over Bluetooth.
- **Runtime**: QuickJS (2024-01-13) + Skia, full ES2023, **ESM only** — no CommonJS `require()`, no top-level await. The API surface is a documented list, not the browser's: if an API is not in the official reference, it does not exist here (see the API discipline lesson below and `API-AUDIT.md` beside this skill).

- **Voice interaction — post-MVP adjustment (GO, 2026-10-24)**: Rokid AIUI Agents can interact by voice (ASR input + TTS replies), and GO has flagged that the current fleet's designs are all operation/gesture-driven. The voice-interaction rework (voice flow as a primary channel: spoken input/commands, voice confirmation/correction, TTS feedback) is DEFERRED until the current MVP ends — do not change in-production designs for it now; it belongs to the post-MVP interaction-definition phase, same as the UI unification below.

- **Gestures first, minimal buttons (GO, 2026-10-24)**: the temple touchpad is the primary controller — tap = confirm (`Enter`), double-tap = back (`Backspace`), swipe = scroll/switch (`ArrowUp/Down`), head-steady + nod = gaze confirm; single-finger long-press wakes the assistant, two-finger long-press fires the AI Shortcut Command (a fixed text, ≤500 chars, delivered to a chosen agent — a hardware entry that bypasses ASR entirely). Full verified gesture table: capability registry entries C8002–C8010. Design pages so the main flow runs on gestures alone; keep on-screen buttons to the minimum and state the agent's gesture mapping in its README. (A fleet-wide UI unification for "too many same-style buttons" is deliberately deferred by GO until all 120 agents are done — do not start it early.)

If a feature cannot be wired to a real API, label it honestly in UI + README as sample/placeholder with the pending link named (see gaze-translate). Never fake a capability.

- **Current phase = MVP (GO, 2026-10-24)**: ship functionally correct agents; do not polish UI or invent interaction refinements now. The interaction model and UI unification get designed only after GO's real-device testing of the MVP fleet, because testing is what defines how interaction should work.

## Production lessons (GO rulings from the JP/KR series fixes, 2026-10-25)

- **Language purity for localized agents.** Every user-visible string — status, hero, rows, marks, guide, TTS lines, SCAN prompts, seed/demo data — is authored in the agent's local language from the start. Only English chrome stays English (page title, button labels, `EVT:` prefix). README documentation is written in the agent's own language (see the repository language rule below). Never build one locale's UI by copying another locale's strings — the JP/KR generator shipped whole Korean UIs in Japanese this way. Machine-verify BEFORE packing: KR builds — kana count = 0 AND CJK ideographs = 0 in UI strings; JP builds — no Chinese-only phrases (guides and SCAN prompts are the usual hiding places). The scan runs on the built files, not just the sources.
- **Green-only palette.** CSS uses the green scale only: `#ffffff` and white `rgba(255,255,255,…)` are banned. The preview renders CSS colors literally (white screenshots), while the real monochrome-green panel maps everything by luminance — so express light/dark directly in greens, with the brightest green `#7dff9e` in the "white" role. The screenshot pipeline blackens the preview page background so the canvas's rounded-corner transparency never reads as white.
- **Buttons follow the UI form.** No shared default button across agents: each UI form/arch gets its own button styling (shape, border, fill logic must read as part of that agent's metaphor). Sole exception: the DEMO button's geometry is fixed by the screenshot pipeline's click point — restyle its skin only.
- **Environment common-sense gate (concept stage).** The setting must be a place people actually wear glasses: commuting, dining, shopping, home, outdoors, social. Bathing/steam/heat settings （温泉 / 汗蒸 / 桑拿） are out — nobody wears glasses there, venues ban electronics, steam/heat damages the device. If a shipped concept fails this review later: retire it in place (keep dir/branch/README, add a retirement note, never delete), replace it in-slot under the same number, and guard the list-sync cron so the retired slug is never re-appended.
- **Regen wipes post-processing.** A generator rebuild rewrites README and package.json from the spec — version bumps and Change Log sections vanish. Pack LAST, after README/version are final; after ANY regen, re-apply the version bump + Change Log, then verify (version grep in package.json and README, pack contents) before pushing.
- **Repository language rule (GO, 2026-10-29).** One repo, never split by language. Facade documents — root README, `ERROR-CODES.md`, category READMEs, self-written skills docs, `mcp/README.md`, `docs/CAPABILITIES.md` — are trilingual: Chinese canonical in place, English and Japanese alongside as `<name>.en.md` / `<name>.ja.md`, a language-switch line after the H1 in every version, and each translation naming the Chinese version/date it follows (Chinese prevails on conflict); upstream aiui-dev docs are not translated. Each agent's own README is single-language in the agent's language — Chinese agents Chinese, `japan/` agents Japanese, `korea/` agents Korean — including its review-submission section; the Studio import block's lead-in line follows the README language while the URL block itself never changes, and verbatim literals (code, quoted system text) stay as they are.
- **Global error codes (GO, 2026-10-28).** Every failure point in every agent maps to the fleet error-code table (repo-root `ERROR-CODES.md`; new codes are assigned by the registry only, never self-taken — see the table's governance section). The bare code (`E####`, e.g. `E2005`) is the ONLY form anywhere — defined in agent code, shown on glasses, read by TTS, persisted in `lastError` (together with the agent's slug + version), and used in debug; NO prefix of any kind (the numeric segment is globally unique on its own; series/agent prefixes were tried and abolished by GO on 2026-10-28); the agent's last error (full code + slug + version + original text) is persisted in `lastError`, and the README carries a 「错误码」 section listing the codes used. `FileReader` does not exist in the Ink runtime — Blob→dataURL goes through `blob.arrayBuffer()` + chunked `btoa` (fleet's first field report: E2005, from AV11).
- **API discipline — official list only (GO, 2026-10-29).** Stood up after AV11 shipped code using `FileReader` — an API the official reference never listed — and the miss was only caught on a real device. The full audit behind this lesson is `API-AUDIT.md` beside this skill (official `documentation/` + aiui-dev references, read end to end on 2026-10-29). The rules, binding on every new agent:
  1. **Trace or don't use.** Every API an agent calls must be findable in the official reference (aiui-dev `references/apis/` or upstream `documentation/3-api/`) with its documented signature. Browser, MDN, Web Speech, or WeChat-mini-program familiarity is NOT evidence an API exists here. If you cannot point at the doc entry, the API does not get used — no exceptions, no "it probably exists".
  2. **The absent list is banned outright** (verified 0 hits in the full official doc tree, or explicitly unsupported): `FileReader`, `sessionStorage`, `XMLHttpRequest`, `URL.createObjectURL`, `DOMParser`, `structuredClone`, `queueMicrotask`, `Notification`, clipboard APIs, `IntersectionObserver`, `MutationObserver`, `ServiceWorker`, `new Worker()`, `canvas.toDataURL()`, `canvas.toBlob()`, `canvas.captureStream()`, WebGL, `OffscreenCanvas`, `getDisplayMedia`, `track.applyConstraints()`, `getPhotoCapabilities()/getPhotoSettings()`, `TextDetector`/`FaceDetector` (no OCR API), DOM-style `onclick=` handlers, `App()`/`Page()`/`Widget()` registration calls, `speechSynthesis.getVoices()` and TTS cancel/pause/resume, `navigator.permissions`, Web Crypto encrypt/decrypt and RSA/ECDSA/JWK. Static check greps for these; any hit fails the build.
  3. **Mind the Ink version floor.** APIs arrived by runtime version (0.15 sensors, 0.17 media capture + OPFS, 0.18 Widgets/Agent Workers/Web Audio/geolocation, 0.19 `convertToBlob`/`createImageBlob` — full table in `API-AUDIT.md`). Design against the `app.json.engine` floor; version-sensitive or host-optional APIs get an existence guard (`typeof` check, the official TTS tutorial's own pattern, or `wx.canIUse()` — which proves the interface exists, never that the device can or the user allowed it).
  4. **Documented-shape only.** Even for listed APIs, use only the documented form: `MediaRecorder` takes exactly the four documented mime strings and `isTypeSupported` is static-only; mic modes live only in `getUserMedia` audio constraints (never in ASR or the wx recorder); `promptStreaming` is a polling `read()` object, not a WHATWG stream; `LanguageModel.availability()` returns exactly `available`/`unavailable` — no intermediate states; sensors read `null` before the first reading; ASR `error` category strings have NO official enumeration, so never branch on MDN Web Speech error names — fall back to the generic error code unless a value is device-verified.
  5. **wx is a subset.** wx-compatible APIs cover only what `weixin-compatible-apis.md` lists; never import a WeChat API from memory.

- **Badge definitions are frozen.** Root-README series badges are only the five （指向性 / 注意力 / 路缘坡 / 游戏 / 影视听）; never add or change a badge definition without GO's explicit instruction （影视听 was added by GO on 2026-10-28 for the AV audiovisual series: shields color E91E63, legend SVG `assets/badges/badge-av.svg`). An agent outside those series carries an existing series badge only when it functionally belongs to that series — don't force it (JP/KR attribution mapping lives in MEMORY).

## Steps

1. **Design** — one life problem; name the directionality core (GAZE / HEAD / MIC4 / GEO-H / SCAN) and the exact APIs used, each traced to its official reference entry (API discipline lesson). Check the red lines first, pass the default-capability conflict check (the agent's core must not be a built-in feature + a small twist) and the environment common-sense gate above.
2. **Develop** — in `<slug>/` (app.json + AGENTS.md + app.js + pages/*.ink). Project root must carry `.aixignore` excluding `.agents/`, `.aix/`, `artifacts/`, `*.aix`, `skills-lock.json`, `node_modules/`.
3. **Static check** — JSON parse of app.json, JS syntax parse, permissions match features actually used (names from the seven-name table only). API discipline: grep the built files for the absent-list battery (API discipline lesson, rule 2) plus the stale patterns `Page(`, `App(`, `Widget(`, `require(`, `onclick=`, and the legacy `workers` field — any hit fails; every non-trivial API call must trace to the official reference. Canvas code must call `ctx.flush()` after drawing. Error-code wiring: every failure point maps to a global error code in bare `E####` form (repo-root `ERROR-CODES.md`), no bare original-text errors surfaced to the user, and `FileReader` must not appear anywhere (absent from the Ink runtime). For localized agents, also run the language-purity scan on the built files (see Production lessons). The official aiui-dev `checklist.md` (§6 API checks, §8 executable verification, §9 three-tier completion reporting) applies on top of this step.
4. **Pack** — `aix pack . -o <slug>.aix`; record the size. A pack that suddenly balloons means `.aixignore` is broken.
5. **Preview** — screenshots of ALL pages via the local preview pipeline (skill `rokid-preview-screenshots`); save to repo-root `screenshots/<slug>/`.
6. **README** — The README's very top (immediately after the H1 title) MUST carry the Studio import block, copy-ready: a line 「**Studio 导入地址**（复制到 Global AIUI Studio 的 Import Project 输入框）：」 followed by a fenced code block containing only `https://github.com/sakai55/rokid/tree/agent-<slug>` (GO, 2026-10-24). The branch copy of the README keeps the same top block. The README must also contain: features, directionality usage, permissions, pack/preview commands, device-test info table (Studio name / Version / Category / Intent / Agent ID / status — backfilled after Studio import), a 「错误码」 section (the global codes this agent can surface, bare form such as `E2005`, plus the report convention), a 「预览截图」 section embedding `../../screenshots/<slug>/*.png` (agent now lives two levels deep: `<分类>/<slug>/`), and the segmented 「提审资料 (Review Submission)」: Feature Description (≤500 chars), Opening Message (≤500, Markdown), Preview Media (3–5 files, ≥1 image + ≥1 video; video backfilled at device stage), Change Log split into Features added / Improvements / Fixes per Build.
7. **GitHub sync** — via terminal `git`/`gh` (logged in as sakai55; GitHub ops are pre-approved): push to main at `<分类>/<slug>/` (category folder by ID first letter: DI→directional, WA→watch, HO→hold, CO→cover, FI→filter, DU→dual, RE→review, CU→cue, SO→social, BO→body, AM→ambient, CC→curb-cut, GA→games, unnumbered→base), `aix/<slug>.aix` in the repo, screenshots to `screenshots/<slug>/`, and mirror the same file set to branch `agent-<slug>` **at branch root** (branch root = project root; keep it clean — no subdirectory copies, no stray .aix).
8. **Register** — mark the agent ✅ in the 50-agent PLAN progress table with AIX size, screenshot count, branch name. The root README agent list is NOT maintained by a separate cron anymore (the `rokid-agent-list-sync` cron was cancelled 2026-10-26): since then the daily boutique run prepends new rows at the TOP of the list itself, once, after its batch is pushed (the list sits right after the Studio-import section and is newest-first since 2026-10-28 — never append at the tail); outside that run, do not edit the list by hand.
9. **Device test & submission (GO-triggered only)** — GO imports in Global Studio via `tree/agent-<slug>`, Device Debug → Package and Save, Hi Rokid updates the glasses resource package, voice-opens the agent. Only when GO says 「真机测试完成了」 may it be submitted for review in Studio, pasting the README's 提审资料 verbatim, then backfill the device-test table.

# Rokid 頭部運動ミニゲーム
[中文](SKILL.md) | [English](SKILL.en.md) | 日本語
本書は中文版（2026-10-29 時点）を正本とする。解釈に食い違いが生じた場合は中文版を優先する。

GA ゲームの技巧を扱うレイヤーである。制作の共通手順――能力のレッドライン、統治ルールである三つの関門、9ステップの SOP、preview / README / GitHub 同期――は `rokid-agent-sop` に集約されている。ここでは、入力が頭部運動だけであるゲームに固有の内容だけを扱う。統治ルールのもとでゲームは、ゲーム向けの緩和によってループの関門を通る（単一のメカニクスと、開始 / 勝敗 / スコアまでを備えた完結したプレイのループ）。新規制作では単体のゲームとして出荷せず、単一のコレクションハブ `head-games-hub` へ組み込む。単体で作った GA01〜GA26 は、構築済みの形のままアーカイブとして残す。

## 憲法 — 円を描く動きは禁止（GO、2026-10-24）

首は球関節ではない。円を描く動きは、頸椎が限界位置にある状態で負荷をかけ続け、めまいも引き起こす。そのためシリーズ全体を通して、**動きは分節化する**ことだけを許す。

> **中心 → 1つの方向 → 保持 → 中心へ戻る → 次の方向。** 円を描いてはならない。一方の限界位置から反対側の限界位置へ直接振ることも、頭を素早く振ることも禁止である。

すべてのラウンドは、このルールの短い読み上げから始める。準備画面、AGENTS.md、README、審査提出用の文面でも、同じルールを同じ言葉で述べる。ゲームごとに言い換えてはならない。

## 安全ライン（全ゲーム必須、任意ではない）

- 動きはゆっくり、小さく。軽く伸びを感じるところで止め、痛みが出るところまで行ってはならない。無理に伸ばさない。息も止めない。
- 中心へ戻る動作は、どの2方向の間にも必ず挟む必須のステップである。これを飛ばした動きはスコアに数えない。
- プレイを始める前に、座るか立った姿勢で体を安定させる。痛み、めまい、しびれ、吐き気、動悸のいずれかが出たら、その場で中止する。
- 1ラウンドは60〜180秒とする。タイムアウトになったらラウンドを打ち切り、引き延ばさずにスコアを報告する。
- 医療行為ではない旨の免責は、例外なくすべての場所に置く（準備画面、README、提出用文面）：本シリーズは娯楽と日常の活動を目的とし、診断、治療、リハビリテーションではない。頸部の疾患がある、めまいがある、術後である、頭頸部を負傷したことがある場合は、事前に医師へ相談すること。

## 技術面の正直さ（センサーの事実、2026-10-24 検証済み）

- **アイトラッキングはない。** ゲームでいう「見る」とは、頭の向きとその安定性だけを指す。
- **`onHeadGesture` について公式にドキュメント化されているのは `'nod'` だけである。** shake / turn / tilt のジェスチャイベントが来ると主張してはならない。「いいえ」の回答は、横を向いて静止する動作で表す（GA16）。これは shake ではないと明示する。
- センサーの読み取り値は、最初のサンプルが届くまでは `null` である（`quaternion`、`timestamp`）。サンプリングが始まったかどうかは `activated` / `hasReading` で判定し、`null` を 0 として扱ってはならない（公式のデバイスドキュメントによる。2026-10-29 の全量監査でも確認した）。
- yaw / pitch / roll はいずれも、ラウンド開始時にキャリブレーションした中心を基準として、`AbsoluteOrientationSensor` のクォータニオンから求める。**符号は仮定せず、学習で決める**。キャリブレーション時の音声案内が符号を教える（「頭を下げてください」で下向きを、「左を向いてください」で左向きを、「左に傾けてください」で左への傾きを学習する）。反対方向は符号を反転させたものになる。
- 判定値の目安（ゲームごとに AGENTS.md へ明記し、再調整は実機段階でのみ行う）：到達判定はおよそ27°、中心復帰は10°未満、方向が成立するのは約0.8秒静止してからとする（安定性によるゲートをかけ、ドキュメント化された経過時間によるフォールバックも用意する）。
- Web プレビューにはセンサーが存在しない。この経路は SKIP / デモと表示し、合格を装ってはならない。グラスに**呼吸センサーはない**。呼吸を扱うゲームは音声でペースを示すものであり、呼吸そのものを測定することは決してない（GA17）。

## ゲームの形

- ページは1つ（`pages/index/index`）、状態は3つだけ（準備 / プレイ中 / 完了）、メカニクスは1つ。それ以外は入れない。メニューも、設定も、多段構成も作らない。難易度を変える数値は1つだけ（回数か秒数のどちらか）とする。
- プレイ中の画面に出すのは最大で3要素まで。大きく表示する方向または目標、回数または進捗、短いヒント1つである。それ以外はすべて音声で伝える。TTS が案内し、カウントし、結果を読み上げる。
- テンプルのタップは開始 / 確認 / もう一度プレイ、に割り当てる。nod を確認に使うのは、そのメカニクスがそう定める場合だけである。ダブルタップはホスト側の「戻る」であり、横取りしてはならない。各 README にジェスチャ対応表を記載する。
- **権限は設計上ゼロとする**：`permissions: []`（プラットフォームの7つの権限名のどれも、センサーや TTS をゲートしていない。どちらもゲートの対象外である）。制作のどこかで権限が必須になる事態が起きたら、黙って追加せず、報告したうえで計画に記録すること。
- CSS は緑の階調のみを使う（最も明るい緑 `#7dff9e` が「白」の役割を担う。純白も、白の rgba も使わない）。ボタンのスタイルは各ゲームの UI の形に合わせて個別に決める。キャンバスは480×352とする。

## 設計ルール

- **焼き直しは禁止である。** 構築に入る前に、そのゲームの AGENTS.md へ、既存の GA ゲームの中で最も近いものを挙げ、メカニクスの違いを1点だけ明記する。その違いを言葉にできない企画は、その時点で終了とする。
- 試行の順序は固定し、ドキュメントに残す（実行時のランダム性は入れない）。順序自体が設計の一部であり、AGENTS.md と計画の双方に記載する。
- シーケンスも憲法に従う。時計の文字盤の位置は、間に中心への復帰を挟んで1つずつ訪れる位置であって、なぞる軌跡ではない（GA05）。追従シーケンスには、時計回りで隣り合うステップを1つも含めない（GA10）。

## 判定パターン（再利用できる技巧）

- **復帰ゲート** — 頭が実際に復帰バンドの中へ戻るまで、次の目標は出さない（GA10 の厳密な形。試行ごとの猶予期間を認める形は、ドキュメント化された変種として GA09 にある）。
- **バンドと静止保持** — ヒットとは、目標バンドに入り、約0.8秒とどまることである（GA13。精密版は目標角度 ±5° のバンド、GA21 / GA22）。
- **中心で止まる** — 復帰の動作そのものを判定する。±5° の範囲内で止まり、反対側へ −5° を超えて行き過ぎないこと（GA24）。
- **タイミングウィンドウ** — 動作にかける時間までを指定する。回転は3.0〜5.0秒（GA23）、スキャンは1パス8秒以上とし、速すぎた場合はやり直しにする（GA15）、ビートのウィンドウは ±300 ms（GA11）。
- **静止** — 角度変化の合計を5°未満に抑える。短い猶予期間と、回数に上限のあるリセットを用意し、上限を超えたら強制的に休憩へ移る（GA07 / GA14）。
- **距離はバンドだけを伝える** — 目標を隠す形式のプレイでは、伝えるのはバンドだけ（近い / より近い / 遠い）とする。発話はバンドが変わったときだけ行い、答えそのものは決して伝えない（GA18）。
- **ラダー** — 保持時間を2 / 3 / 4 / 5 / 6秒と段階的に伸ばし、段と段の間には復帰を挟む（GA25）。記憶の要素ではステップ数が3→4→5と増える（GA12。6方向を使う形が GA26）。

## 制作レッスン（GA 固有、SOP への上乗せ）

- **pack の前にロジックのハーネスを通す**：各ゲームの判定ロジックにはスクリプト化したハーネスを用意して実行し、合格数（例：33/33）をバッチとともに報告し、計画にも記録する。ハーネスの結果数がないゲームは、完成とはみなさない。
- **pack は最後に行う** — README.md と AGENTS.md が確定してから pack し、両ファイルがパックに含まれていることを `aix list` で確認する（GA03 / GA04 は当初この2ファイルなしで出荷され、pack し直すことになった。pack の後に README / AGENTS を直したら、再 pack と再確認が必須になる）。
- スクリーンショット：3つの状態を、正確に480×352で、互いに見分けがつく形で撮る。プレビューの枠の角丸部分の透明領域に限って現れる白に近いピクセル（角あたり約92 px）は、既知のプレビュー側のアーティファクトであり、UI が白を使ったことにはならない。UI 自体は緑の階調を維持する。
- 本体のレイアウト：`games/<slug>/` + `aix/<slug>.aix` + `screenshots/<slug>/` とし、ブランチ `agent-<slug>` のルートには当該ゲームの7ファイルだけを置く。`games/README.md` への新規ゲームの行は、本体へのプッシュと**同じ**バッチに含める（GA24〜GA26 のバッチではこの記載が漏れ、親側がフォローアップのコミットで補うことになった）。ルート README のエージェント一覧は、手で編集してはならない。

## 実機で未解決のリスク（検証済みと主張しない）

- **顎引きのバンド（GA06、GA20 の中にも組み込まれている）**：本物の顎引きは主に水平方向への移動であり、姿勢センサーではほとんど捉えられない。本ゲームが検出しているのは、その動きに含まれる小さな pitch 成分である（バンドは14〜20°、20°以上は不成立とする）。実機段階では、自然な顎引きがこのバンドに収まるかを確認しなければならない。収まらない場合は、しきい値を調整するか、正直に作り直すこと。
- 左右への傾きの呼び方（GA14）は、実機で確認が取れるまでは表示上の取り決めにすぎない。
- すべてのしきい値（到達 / 復帰 / 静止時間）はプレビュー段階の値である。最終調整は実機での感触を優先し、提出は GO が「実機テストが完了した」と伝えた後にのみ行う。

## このスキルのバージョニング

このスキルは、同じ場所で改訂を重ね、semver で管理する。

- **patch**（1.0.x）：文言の修正、例の追加、ゲーム単位の注記。
- **minor**（1.x.0）：判定パターンの追加、制作レッスンの追加、ロスターや状態の更新。
- **major**（x.0.0）：憲法または安全ラインの変更。この場合は、出荷済みのすべてのゲームについて、README とゲーム内の文面を新しい内容に照らして再点検しなければならない。

改訂のたびに、上部の `version:` を引き上げ、下部へ変更ログを1件追加する（日付、制作の実績から何を学んだか、何を変更したか）。あわせて、同じターンで導入済みミラーの `~/workspace/custom-skills/rokid-head-games/SKILL.md` を更新し、両方を1つのコミットでプッシュする。GA に限らずすべてのエージェントに当てはまる教訓は、ここに重複して書かず、`rokid-agent-sop` 側へ入れる。

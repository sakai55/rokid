# Rokid 頭部運動ミニゲーム
[中文](SKILL.md) | [English](SKILL.en.md) | 日本語
中文版（2026-10-29 時点）からの翻訳。齟齬がある場合は中文版が優先する。

GA ゲーム向けの技巧レイヤー。共通の制作パイプライン（能力のレッドライン、統治する三つの関門、9ステップの SOP、プレビュー/README/GitHub 同期）は `rokid-agent-sop` にある。本スキルは、入力のすべてが頭部運動であるゲームに固有のものだけを追加する。統治ルールのもとでは、ゲームはゲーム向けの緩和によりループの関門を通る（単一の仕組みと完全なプレイのループ：開始 / 勝敗 / スコア）。新しい制作では、ゲームを単独で出荷するのではなく、単一のコレクションハブ `head-games-hub` に統合する。単独の GA01〜GA26 は構築されたままアーカイブとして残る。

## 憲法 — 決して円運動をしない（GO、2026-10-24）

首はボールジョイントではない。円運動は頸椎の極限位置に連続して負荷をかけ、人をめまいにさせる。そのため、シリーズ全体では**分段運動のみ**を使う。

> **中心 → 一方向 → 保持 → 中心に戻る → 次の方向。** 決して円運動をせず、一つの極限から反対の極限へ直接振ることもせず、頭を速く振ることもしない。

すべてのラウンドは、このルールを短く話した形で始まる。すべてのゲームの準備画面、AGENTS.md、README、審査提出用のコピーは、同じ言葉で同じルールを述べる。ゲームごとに言い換えてはならない。

## 安全ライン（すべてのゲームで任意ではない）

- 遅く、小さい範囲で：軽い伸びのところで止め、痛みのところでは決して止めない。無理をせず、息を止めない。
- 中心に戻ることは、任意の二方向の間の必須ステップである。これを省略した動きは決してスコアにならない。
- プレイの前に、座るか立って安定させる。痛み、めまい、しびれ、吐き気、動悸があれば直ちに中止する。
- 1ラウンドは60〜180秒。タイムアウトでラウンドを終了し、引き延ばさずにスコアを報告する。
- 非医療の免責事項をあらゆる場所に記載する（準備画面、README、提出用コピー）：娯楽と日常活動であり、診断、治療、リハビリテーションではない。頸部の疾患、めまい、術後、頭頸部のけががある場合は、先に医師に相談すること。

## 技術的な正直さ（センサーの事実、2026-10-24 に検証済み）

- **アイトラッキングはない。** ゲームにおける「見る」とは、頭の向きと安定性であり、それ以外ではない。
- **`onHeadGesture` は公式には `'nod'` についてだけドキュメントに記載されている。** shake / turn / tilt のジェスチャイベントを主張してはならない。「いいえ」の答えは、安定して保持した横向きであり（GA16）、明示的に shake ではない。
- センサーの読み取りは、最初のサンプルが来るまで `null` である（`quaternion`、`timestamp`）。サンプリング状態は `activated` / `hasReading` から判断し、`null` の読み取りを 0 として扱っては決してならない（公式のデバイスドキュメント、2026-10-29 の全量監査で確認）。
- Yaw / pitch / roll はすべて、ラウンド開始時に校正した中心を基準とした `AbsoluteOrientationSensor` のクォータニオンから導出する。**符号は学ぶものであり、決して仮定しない**：校正のプロンプトが符号を教える（「頭を下げてください」で下方向を学び、「左を向いてください」で左方向を学び、「左に傾けてください」で左傾斜を学ぶ）。反対方向は逆の符号である。
- 典型的な判定値（ゲームごとに AGENTS.md に記載し、デバイス段階でのみ再調整する）：到達は約27°、中心復帰は10°未満、方向は約0.8秒安定した後にのみ数える（安定性でゲートし、ドキュメントに記載された経過時間のフォールバックを備える）。
- センサーは Web プレビューには存在しない。その経路は SKIP / デモとラベルを付け、偽の合格にしては決してならない。グラスには**呼吸センサーはない**。呼吸ゲームは音声でペースを決め、呼吸を測定することは決してない（GA17）。

## ゲームの形

- 1ページ（`pages/index/index`）、状態は三つだけ（準備 / プレイ中 / 完了）、仕組みは一つ、それ以外は何もない。メニューも、設定も、多段階の構造もない。難易度はちょうど一つの数値（回数か秒数）で動く。
- プレイ中の画面には最大で三つだけを表示する。大きな方向や目標、回数や進捗、短いヒントが一つ。その他はすべて話す。TTS が案内し、数え、結果をアナウンスする。
- テンプルのタップは開始 / 確認 / 再プレイ。nod は仕組みがそう定める場所でのみ確認とする。ダブルタップはホストの戻るであり、決して横取りしない。各 README にジェスチャ対応を記載する。
- **設計上、権限はゼロ**：`permissions: []`（プラットフォームの七つの権限の表にあるどの名前も、センサーや TTS をゲートしない。どちらもゲートされていない）。いずれかのステップで権限が強制されることがあれば、報告し、計画に記録すること。黙って追加しては決してならない。
- 緑の色調のみの CSS（最も明るい緑 `#7dff9e` が「白」の役割を果たし、純白や白の rgba は使わない）、ボタンは各ゲーム自身の UI の形に合わせてスタイルし、キャンバスは480×352である。

## 設計ルール

- **塗り替えはしない。** 構築の前に、ゲームの AGENTS.md に最も近い既存の GA ゲームを挙げ、一つの仕組みの違いを述べる。違いを述べられなければ、そのコンセプトは終了する。
- 固定され、ドキュメントに記載された試行シーケンス（実行時のランダム性はない）：順序は設計の一部であり、AGENTS.md と計画に記載する。
- シーケンスも憲法に従う：時計の位置は、間に中心復帰を挟んで訪れる位置であり、振り回すものではない（GA05）。追従シーケンスには時計回りに隣接するステップを一つも含めない（GA10）。

## 判定パターン（再利用可能な技巧）

- **復帰ゲート** — 頭が実際に復帰バンド内に戻るまで、次の目標は決して現れない（GA10 の厳格な形。試行ごとの猶予はドキュメントに記載された変種である、GA09）。
- **バンドと安定保持** — ヒットとは、目標バンドに入って約0.8秒留まることである（GA13。精密な形：目標角度 ±5° のバンド、GA21/GA22）。
- **中心で止まる** — 復帰そのものを判定する：±5° 以内で止まり、反対側の −5° を超えて行き過ぎないこと（GA24）。
- **タイミングウィンドウ** — 動きは定められた時間でなければならない：回転は3.0〜5.0秒（GA23）、1回のスキャンパスは8秒以上で、速すぎれば再スタート（GA15）、ビートのウィンドウは ±300 ms（GA11）。
- **静止** — 角度変化の合計が5°未満で、短い猶予と上限のあるリセット回数を設け、その後は強制的に休憩させる（GA07/GA14）。
- **距離バンドのみ** — 隠れた目標のプレイでは、バンドだけを話す（近い / より近い / 遠い）。バンドが変わったときに話し、答えを決して話さない（GA18）。
- **ラダー** — 2/3/4/5/6秒の段階的な保持で、段の間に復帰を挟む（GA25）。記憶は3→4→5ステップに増える（GA12。六方向の形は GA26）。

## 制作レッスン（GA 固有、SOP への追加）

- **パックの前にロジックのハーネス**：各ゲームの判定ロジックはスクリプト化されたハーネスで実行し、合格数（例：33/33）をバッチとともに報告し、計画に記録する。ハーネス数がないゲームは完了ではない。
- **パックは最後** — README.md と AGENTS.md が最終になってからパックし、パックに両方が含まれていることを `aix list` で確認する（GA03/GA04 は最初、両方なしで出荷され、再パックしなければならなかった。パック後の README/AGENTS の編集は、再パックと再確認を意味する）。
- スクリーンショット：三つの状態、ちょうど480×352で、互いに区別できること。プレビューフレームの角の丸みの透明部分に限定されたほぼ白のピクセル（角ごとに約92 px）は、既知のプレビューアーティファクトであり、UI の白ではない。UI 自体は緑のスケールを維持する。
- 本体のレイアウト：`games/<slug>/` と `aix/<slug>.aix` と `screenshots/<slug>/`。ブランチ `agent-<slug>` のルートにはゲームの7ファイルちょうどを置く。`games/README.md` における新しいゲームの行は、本体のプッシュバッチと**同じ**バッチに入れる（GA24〜GA26 のバッチコミットはこれを漏らし、親が後続コミットで修復しなければならなかった）。ルート README のエージェントリストは決して手編集しない。

## 未解決のデバイスリスク（検証済みと主張しない）

- **顎引きバンド（GA06、GA20 の内部にもある）**：本当の顎引きは主に水平移動であり、姿勢センサーではほとんど見えない。ゲームはその小さいピッチ成分を検出する（バンドは14〜20°、20°以上は拒否）。デバイス段階では、自然な顎引きがバンド内に収まることを確認しなければならない。収まらなければ、しきい値を調整するか、正直に作り直すこと。
- 左右の傾斜の命名（GA14）は、デバイスで確認されるまでは表示上の慣例である。
- すべてのしきい値（到達 / 復帰 / 安定時間）はプレビュー段階の値である。実機の感触が最終的な調整を決め、提出は GO が「実機テストが完了した」と言った後にのみ行う。

## このスキルのバージョニング

このスキルはその場でイテレーションし、semver を使う。

- **patch**（1.0.x）：文言の修正、例の追加、ゲームごとのメモ。
- **minor**（1.x.0）：新しい判定パターン、新しい制作レッスン、ロスターや状態の更新。
- **major**（x.0.0）：憲法や安全ラインの変更。その場合、出荷済みのすべてのゲームの README とゲーム内コピーを、それに対して再確認しなければならない。

変更のたびに、上の `version:` を上げ、下に変更ログのエントリを追加し（日付、制作の実行から何を学んだか、何が変わったか）、同じターンでインストール済みミラー `~/workspace/custom-skills/rokid-head-games/SKILL.md` を更新し、両方を一つのコミットでプッシュする。すべてのエージェントに当てはまる教訓（GA だけではない）は、代わりに `rokid-agent-sop` に入れる。ここに重複させてはならない。

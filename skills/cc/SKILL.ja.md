# Rokid Curb-Cut Design

[中文](SKILL.md) | [English](SKILL.en.md) | 日本語
本書は中文版（2026-10-29 時点）をもとに作成した。内容に食い違いがある場合は中文版を正とする。

CC Agent の設計を扱う層である。制作手順の共通部分（能力面のレッドライン、全体ルールとしての三つのゲート、9 ステップの SOP、パッキング／プレビュー／README／GitHub 同期）は `rokid-agent-sop` が担い、本 skill ではカーブカットシリーズ固有の決め事だけを扱う。CC と名乗れるのは、次の 3 点をすべて満たす Agent に限る。CC 番号が付いていること。プロジェクトが `curb-cut/<slug>/` 配下にあること。下記の「立ち上げの三問」をすべて通ること。

## カーブカット効果とは

カーブカット効果（2026-10-24 に GO が Wikipedia の該当記事を指定）とは、障害のある人のために作ったものが、想定した利用者層をはるかに超えて広く使われ、喜ばれるようになる現象をいう。車椅子のために切り下げた歩道の縁はベビーカーや台車、スーツケースにも役立ち、聴覚障害のある人のための字幕は騒がしいバーにいる健聴者にも役立つ。ユニバーサルデザインの一部だが、波及はたいてい意図せず起きる。シリーズの PLAN が引く Reid の警告が、本シリーズの前提になる。アクセシビリティを「みんなに役立つから」という理由に従わせると、障害のある本人のために個別に作り込む部分こそ真っ先に削られてしまう。だから本シリーズでは、本人の障壁を最優先し、汎用的な利便性のために薄めることはしない。波及はあくまで結果であり、目的ではない。

## 立ち上げの三問 ― すべての CC の README に明記する

1. **スロープ本体。** 対象はどの集団か。壊れているのはどのチャネルか（見る／聞く／話す／動く／覚える／注意を向ける）。判定はシンプルで、その集団を外した途端に Agent として成立しなくなること。障害のラベルを貼っただけの汎用 Agent としてまだ成立するなら却下する。
2. **チャネルの置き換え。** 壊れたチャネルは「配慮」で補うのではなく、設計から外す。
   - 全盲／弱視 → **画面依存ゼロ**：全工程を TTS とうなずき／首振りで完結させる。画面は、目の見える支援者が状況を追うためのミラー表示に限る。
   - 聴覚障害／重度の難聴 → **音声依存ゼロ**：情報はすべて視覚で出す（バナー、方向矢印）。この利用者に TTS は届かないため、TTS に内容を持たせてはならない。
   - 片手／片麻痺 → 眼鏡の**手操作ゼロ**：操作は頭の動きと音声のみとし、作業手順そのものも片手でできる形に書き換える（テーブルの縁、体、膝を固定代わりに使う）。
   - 失語症 → 入力は見ることとうなずきで受け、出力は本人の代わりに**周囲の人へ TTS で伝える**形にする。
   - 認知／注意 → 一度に出すのは 1 項目だけ、画面の情報量は最小限にし、リマインダーではなく証拠の再生で支える（CC11 参照）。
3. **波及マップ。** ここに書けるのは、障害のない人が置かれる*状況的な*障害だけである。赤ちゃんを抱えている状態は一時的な片手、騒がしい市場は一時的な難聴状態、外国語の環境は一時的な失語状態にあたる。荷物を引いて移動する人は、車椅子ユーザーと同じ制約を一時的に抱える存在である。この節で「誰でも使える」は禁止表現とする。

## 慧眼に関する除外ルール

この眼鏡には、汎用の視覚認識（慧眼識別：ものの認識／文字や標識の読み取り／場面の説明）に加え、翻訳、テレプロンプター、会議の文字起こし、地図ナビ、AI の質疑応答が標準で入っている。これらは本シリーズでは作らない。企画ごとの判定基準は次のとおり。**慧眼に一度聞けばその場で答えが返るものは作らない。** 認識を使ってよいのは、閉じたループの中の一工程として使う場合に限る。対象を登録する → 見守る／カバーする／数える／照合する → 再生する、または判定を出す、という形である。本シリーズで実績のあるループは次の 5 つ。

- **カバー漏れがないことの証明** ― CC01 `drop-search`：床を 6 セクターに分け、1 つずつ確認済みにしていく。「見つからなかった」という判定は 6/6 を終えた後にだけ出せるもので、初期値として出してはならない。
- **登録 → 見守り → 判定** ― CC02 `my-bus-watch`：見守るのは登録したバス路線だけ。到着のたびに出す判定は 1 つだけ（自分のバス／自分のバスではない／読めない場合は正直に SKIP。推測はしない）。
- **過程を数える** ― CC03 `step-count-down`：階段の最上段で段数の合計を登録し、一段ずつ減らしながら進め、「一番下に着いた」ことを明示する。
- **順序の照合表** ― CC04 `color-order-check`：色は読み上げた名前として順序表に記録し、位置ごとに再照合する（壊れた色のチャネルを、色そのものを使って直そうとしない）。
- **証拠の再生** ― CC11 `left-home-proof`：外出の途中でチェックポイントを撮影しておき、外出後の再生で「戻って確認する」繰り返しを断つ。

## 標準機能との衝突チェック

着手前に、企画を標準搭載能力のベースラインと照合する（2026-10-25 の監査、`~/workspace/rokid/audit-builtin-conflicts/REPORT.md`）。本体が標準機能そのもので、そこに小さなひねりを足しただけの企画は第 1 段階であり、対象外とする。SOP の全体ルールにより、組み直して審査に出すこともしない。教訓として残っているのが CC07 `last-sentence` である。探索フェーズで作ったものだが、標準搭載の文字起こし／字幕との切り分けは GO の確認待ちとして指摘された。標準機能にこれだけ近い企画は、作る*前に*切り分けを再確認し、GO に上げること。制作の勢いで決着させてはならない。

## 全体ルールとの関係（2026-10-26）

CC01–CC08 は探索フリート時代の形（仕組み 1 つだけの薄い構成）であり、そのまま保管する。新規の CC は「立ち上げの三問」に加えて SOP の三つのゲート（シナリオ／ループ／厚み）も通すこと。厚みはシナリオ単位で足すか、シナリオ単位で統合して確保する。手本はブティックラインでの CC の作り直しである（CC10 `freeze-step-cue` はリズムセットとセッション記録を持たせて v2.0.0 として現地で作り直し、CC12–CC14 は 3 ページのブティック版として制作）。薄い 1 機能構成を CC 番号で量産してはならない。

## 医療・健康まわりの線引き

健康に関わる Agent（CC03 の階段、CC10 の歩行凍結へのキュー、CC16 の失語症、CC18 の声量）は生活支援に限る。扱ってよいのはリズムのキュー、フィードバック、リマインダーまでで、診断や治療は扱わない。README と審査提出用の文案には、その旨を必ず明記する。

## 体裁と台帳

- 台帳と番号の正は `~/workspace/goals/20-agent-rokid-aiui/files/PLAN-20-CurbCut-Agents.md`（CC01–CC20）と `curb-cut/` ディレクトリとする。ルート README の一覧で使うシリーズバッジはカーブカット（バッジ定義は凍結。SOP 参照）。
- なぜ胸装着デバイスではなく眼鏡なのかは、すべての CC の設計に含める論点である。カメラが利用者本人の視線と同軸にあること、表示が（残っている）視野の中に出ること、頭の向きがそのまま注意のポインタになること。この 3 点があるため、本シリーズの利用者にとって胸装着デバイスは「劣る選択肢」ではなく選択肢にすらならない（座ったまま高い棚を見るときの視界を写せず、両手が車椅子のリムにかかっている利用者には何も表示できない）。

## この skill のバージョン管理

本 skill はインプレースで更新し、semver で管理する。

- **patch**（1.0.x）：文言の修正、事例の追加、出荷済みの CC Agent から得られた新しいループ形状の追加。
- **minor**（1.x.0）：チャネルの置き換えに関するルールの追加、除外事例の追加、監査の教訓の追加。
- **major**（x.0.0）：「立ち上げの三問」または「薄めない」原則の変更。

変更時は、冒頭の `version:` を上げ、下記の Change Log に項目を追加し（日付、どの制作で何を学んだか、何を変えたか）、同じターンで導入済みミラー `~/workspace/custom-skills/rokid-curb-cut/SKILL.md` を更新し、リポジトリ側のコピーと同じコミットで push する。CC に限らずすべての Agent に当てはまる教訓は本 skill には書かず、`rokid-agent-sop` 側に入れる。重複はさせない。

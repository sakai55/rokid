# Rokid Curb-Cut Design

[中文](SKILL.md) | [English](SKILL.en.md) | 日本語
中文版（2026-10-29 時点）からの翻訳。齟齬がある場合は中文版が優先する。

CC Agent のデザイン層。生産パイプラインの共通部分（能力のレッドライン、全体を統括する三つのゲート、9 ステップの SOP、パッケージング / プレビュー / README / GitHub 同期）は `rokid-agent-sop` にあり、この skill はカーブカットシリーズに固有のものだけを加える。Agent が CC であるのは、次の 3 点がすべて成り立つ時だけである：CC 番号があること、プロジェクトが `curb-cut/<slug>/` の下にあること、下の企画時の三つの問いを通ること。

## その効果

カーブカット効果（2026-10-24、GO が Wikipedia の記事を指定）：障害のある人のために設計された特徴が、当初の集団をはるかに超える多くの人に使われ、好まれるようになる現象。車椅子のために作られた縁石の切り下げは、ベビーカー、カート、荷物にも役立ち、聴覚障害のある人のために作られた字幕は、騒がしいバーにいる聴力のある人にも役立つ。それはユニバーサルデザインの部分集合であり、波及は通常、意図しないものである。シリーズの PLAN に引用された Reid の警告がこのシリーズを統括する：アクセシビリティが「みんなにとって良い」という考えに従属させられると、まさに障害のある人に向けた個別化されたデザインこそが退けられる。だからここでは、障害のあるユーザーの障壁が第一であり、一般的な利益のために決して薄めない。波及は効果であって、目標ではない。

## 企画時の三つの問い — すべての CC の README に 3 点すべてを載せる

1. **スロープそのもの。** どの具体的な集団か、どのチャネルが壊れているか（見る / 聞く / 話す / 動く / 覚える / 注意を向ける）？ 判定方法：その集団を取り除くと、その Agent は直ちに意味をなさなくならなければならない。障害のラベルを貼っただけの汎用 Agent としてまだ成り立つなら、却下する。
2. **チャネルの改造。** 壊れたチャネルは、配慮でごまかすのではなく、設計から外す：
   - 全盲 / 弱視 → **画面への依存ゼロ**：TTS と うなずき / 首振りで全フローを回し、画面は目の見える手伝い手のための鏡としてだけ使う。
   - 聴覚障害 / 重度の難聴 → **音声への依存ゼロ**：すべての情報は視覚的に出す（バナー、方向の矢印）。TTS はこのユーザーには役立たず、内容を担わせてはいけない。
   - 片手 / 片麻痺 → グラスの**手操作ゼロ**：頭と音声だけで操作し、課題の手順そのものも片手向けに書き直す（テーブルの縁、体、膝を固定具として借りる）。
   - 失語症 → 見ることとうなずきで入力し、出力はユーザーの代わりに**他の人へ TTS で話す**ことで行う。
   - 認知 / 注意 → 1 回に 1 項目だけ、画面上の情報は最小限にし、リマインダーではなく証拠の再生を使う（CC11 を参照）。
3. **波及マップ。** 障害のない人がそれを使うであろう*状況的な*障害だけを名指しする：赤ちゃんを抱えることは一時的に片手になること、騒がしい市場は一時的に聞こえなくなること、外国語は一時的に失語になること、荷物を引くことは車椅子ユーザーの双子であること。「誰でも使える」は、この節で禁止された文である。

## 慧眼の除外ルール

このグラスには、汎用の視覚インテリジェンス（慧眼識別：認識する / 文字と標識を読む / 場面を説明する）に加え、翻訳、テレプロンプター、会議の文字起こし、地図ナビゲーション、AI の質疑応答がすでに搭載されている。それらはここでは作らない。概念ごとに適用する実務上の判定は次の通り：**慧眼に 1 つ質問すればその場で答えが得られるなら、作らない。** 認識は、クローズドループの中の一手順としてだけ現れてよい — 対象を登録する → 見守る / カバーする / 数える / 検証する → 再生するか、判定を出す。ループの形はこのシリーズで実証済みである：

- **カバー範囲の証明** — CC01 `drop-search`：床を 6 つのセクターに切り、1 つずつ確認していく。「見つからない」は 6/6 の後にだけ得られる判定であり、決して初期値ではない。
- **登録 → 見守り → 判定** — CC02 `my-bus-watch`：登録したバス路線だけを見守り、到着ごとに正確に 1 つの判定を出す（自分のバス / 自分のバスではない / 読めない = 正直な SKIP。決して推測しない）。
- **過程を数える** — CC03 `step-count-down`：階段の上部で総数を登録し、一段ずつ数え減らしながら、明示的な「一番下に着いた」を出す。
- **順序の検証表** — CC04 `color-order-check`：色は話された名前として順序表に記録し、位置ごとに再検証する（壊れた色のチャネルを、色そのもので直すことは決してしない）。
- **証拠の再生** — CC11 `left-home-proof`：出かける途中でチェックポイントを撮影し、外出した後の再生で、戻って確かめるループを断ち切る。

## 衝突監査の規律

作る前に、その概念を標準搭載能力のベースラインと照合すること（2026-10-25 の監査、`~/workspace/rokid/audit-builtin-conflicts/REPORT.md`）：本体が標準搭載機能そのもので、小さなひねりを加えただけの概念は第 1 段階であり、対象外とする。SOP の統括ルールにより、組み直したり審査に出したりもしない。記録された教訓：CC07 `last-sentence` は探索段階で作られ、標準搭載の文字起こし / 字幕との区別は GO の確認待ちとして指摘された。概念が標準搭載機能にそれほど近い場合は、作る*前に*その区別を再検討し、GO に示すこと。生産の勢いに決めさせてはいけない。

## 統括ルールとの適合（2026-10-26）

CC01–CC08 は探索フリートの形（1 つの仕組み、薄い）であり、そのまま保存される。新しい CC の作業は、企画時の三つの問いの上に、SOP の三つのゲート（シナリオ / ループ / 厚み）を通す：シナリオごとに厚くするか統合する — ブティックラインの CC の作り直しが手本である（CC10 `freeze-step-cue` はその場で v2.0.0 として作り直され、リズムの集合とセッション記録を持つ。CC12–CC14 は 3 ページのブティック版として作られた）。薄い 1 機能の形を CC 番号の下で再生産してはいけない。

## 健康の境界

健康に触れる Agent（CC03 の階段、CC10 の歩行凍結への合図、CC16 の失語症、CC18 の声の音量）は、生活支援のみである：リズムの合図、フィードバック、リマインダー — 決して診断や治療ではない。README と審査提出用の文案には、その旨を明記しなければならない。

## 形式と名簿

- 名簿と番号の権威：`~/workspace/goals/20-agent-rokid-aiui/files/PLAN-20-CurbCut-Agents.md`（CC01–CC20）と `curb-cut/` ディレクトリ。ルート README の一覧におけるシリーズバッジ：カーブカット（バッジの定義は固定。SOP を参照）。
- グラスであり、胸装着デバイスではない理由は、すべての CC デザインの一部である：カメラはユーザー自身の視線と同軸であり、表示は（残っている）視野の中にあり、頭の向きが注意のポインタである — このシリーズのユーザーにとって、胸装着デバイスは劣る選択肢ではなく、選択肢にすらならない（座っているユーザーが高い棚で見るものを写せず、両手が車椅子のリムにあるユーザーに何も表示できない）。

## この skill のバージョン管理

この skill はその場で更新し、semver を使う：

- **patch**（1.0.x）：文言の修正、例の追加、出荷した CC Agent から得られた新しい実証済みループの形。
- **minor**（1.x.0）：新しいチャネル改造ルール、新しい除外事例、新しい監査の教訓。
- **major**（x.0.0）：企画時の問い、または薄めないルールについての変更。

すべての変更：上の `version:` を上げ、下に Change Log の項目を追加し（日付、どの生産ランが何を教えたか、何が変わったか）、同じターンでインストール済みミラー `~/workspace/custom-skills/rokid-curb-cut/SKILL.md` を更新し、同じコミットでリポジトリ側のコピーを push する。すべての Agent に当てはまる教訓（CC だけではないもの）は、代わりに `rokid-agent-sop` へ入れる — ここに重複させない。

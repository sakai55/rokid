# Rokid デフォルト能力衝突監査 (Built-in Capability Conflict Audit)

[中文](SKILL.md) | [English](SKILL.en.md) | 日本語
中文版（2026-10-29 時点）からの翻訳。齟齬がある場合は中文版が優先する。

**Version: 1.0.1** — バージョン反復ルールは文末を参照。初版の出所：2026-10-25 に全艦隊122個の Agent に対して行われた初の監査（GO の指示）。完全なレポートは保守担当者のワークスペース `~/workspace/rokid/audit-builtin-conflicts/REPORT.md` にある。

## なぜこの skill があるのか

グラス本体には一式の完全な機能が内蔵されている。Agent が内蔵機能の名前を変えて作り直すのは、車輪の再発明である。ユーザーは内蔵機能を開けばよく、その Agent は必要ない。提審でも成り立たない（SOP の Governing rule の厚みゲート：デフォルト能力と同じ本体であれば即座に却下）。この skill は「何を衝突とみなすか」の基準を固定し、新しい Agent の立項時に自己チェックでき、全艦隊を再チェックでき、ルート README の衝突バッジに唯一のデータソースを持たせる。

## デフォルト能力ベースライン（判定前に必ず最新版を確認する）

ベースラインは公式／公開の出所からのみ取り、印象に頼らない。現在のベースライン（2026-10-25 に確定、出所：公式能力登録表 `docs/CAPABILITIES.ja.md` の条目 C1017、C8013、公式グローバル製品ページ、公開レビューの実証）：

1. **リアルタイム翻訳**（89言語）：対話翻訳の字幕、撮影による文字／メニュー／標識の翻訳。AI クイックコマンドには「撮影して中国語に翻訳」がプリセットで用意されている。
2. **リアルタイム字幕（Intelligent Captioning）**：同じ言語の対話をリアルタイムで画面に表示し、字幕は履歴に残り、後から見直せる。
3. **会議の文字起こし + AI 要約**：文字起こしには話者識別が付き、スマート要約を自動生成する。音声メモも内蔵である。
4. **テレプロンプター**：原稿を画面に表示し、朗読の速さ／間合いに合わせて自動でスクロールして追従する。
5. **慧眼識別 / AI 視覚 Q&A**：「Hi Rokid」アシスタント + カメラで、物を見て識別し、文字や標識を読み、場面について質問に答える。
6. **視覚化 AR ナビゲーション**：方向の矢印 + 速度／所要時間／到着時刻を画面に表示する。
7. **パーソナルアシスタント AI Q&A、通知表示、撮影・録画、通話／音楽**。

再チェックの際は、まずベースラインが変わっていないかを確認する（新しい機種、新しいシステムバージョン、公式の新機能はいずれもベースラインを広げる可能性がある）。ベースラインが変わったら、文末のルールに従ってバージョンを上げ、影響を受ける段階を並べ替える。

## 判定基準（3段階、相互排他）

判定の対象は Agent の**本体の仕組み**（ユーザーに代わって行う、その事柄そのもの）であり、借りているチャネルではない。

- **第1段階 ・ 直接衝突**：本体そのものが何らかのデフォルト機能であり、小さなひねりを1層加えただけのもの（トリガーの方法を変える、小さなフィルターを加える、ある時間枠を切り取る）。GO が名指しした見本：`chat-catchup`（SO01）――内蔵字幕はすでに履歴に残り見直せるのに、「頭を振って直近15秒の要約を出す」は小さなひねりにすぎず、余分であると判定された。処置：再構成して提審してはならない（SOP のハードルール）。取り下げるか／草稿を削除するかは GO の裁定を待ち、自動では実行しない。
- **第2段階 ・ 高度な重なり**：本体の大半はデフォルト機能で「ひと言聞く／開く」ことで完了でき、薄い閉ループが1層残るだけのもの（文字を読んだ後に登録／照合を1ステップ加える、Q&A の後に段階的なガイドを1ステップ加えるなど）。残すか否かは GO がクラスターごとに裁定する。裁定前は提審しない。
- **第3段階 ・ テスト待ち**：第1段階でも第2段階でもない、番号付きのすべての Agent を一律にこの段階に帰属させる。その意味は「デフォルト能力との関係は実機テストの後に定性する」であり、「衝突しないことが検証済み」ではない。新しい Agent はデフォルトでこの段階に入り、監査の後に段階を変える。

衝突とみなさない場合（第3段階に帰属させ、レポートに理由を明記する）：デフォルト能力が閉ループの中の1ステップにすぎず、登録 → 待機／区画カバー／段階的なカウント／事後の再生という閉ループが内蔵機能にはないもの（例：`drop-search` の区画カバー探索、`my-bus-watch` の対象路線の待機フィルター）。

## 監査の手順

1. **全集合を列挙する**：リポジトリの分類ディレクトリ配下のすべての Agent を列挙する（ルート README のリストを基準に差集合を確認する。退役して残されているものはリストに入れず、段階分けにも参加しない）。
2. **本体を読む**：PLAN の登記行と README の仕組みの説明を1つずつ読み、本体をひと言で書き出す。仕組みの実装が読めないものは、`pages/index/index.ink` と AGENTS.md を読んで確認し、slug から推測しない。
3. **ベースラインと照らす**：本体を7項目のベースラインと1つずつ照らし、上の節の基準に従って段階を決める。際どいものは「デフォルト機能でどこまで完了できるか、Agent が加えている層は何か」を明記した上で、第2段階か第3段階かを決める。
4. **レポートを出す**：ワークスペースのレポートを更新する（項目ごとの対照表：第1段階はすべて列挙、第2段階はクラスターごとに列挙、第3段階はまとめる）。ベースラインのバージョンと今回の skill のバージョンを明記する。
5. **バッジを同期する**：ルート README のリストの衝突バッジはレポートの段階を基準とする（第1段階＝直接衝突、第2段階＝高度な重なり、第3段階＝テスト待ち）。バッジの定義は凍結されており、同期を口実にバッジの定義を新たに加えたり変えたりしてはならない（GO が 2026-10-25 に裁定）。
6. **裁定の口を残す**：第1段階の処置、第2段階のクラスターごとの残否は、GO の裁定を報告するだけにとどめる。裁定前に削除せず、提審せず、裁定待ちのものを処置済みと書かない。

## 現在の段階分け（v1.0.0 ベースライン下、2026-10-25 に確定）

- 第1段階 14：DI 系 `gaze-translate`、`head-nav`、`parking-return`、`baby-care-hands`、`far-ear`、`ambient-captions`、`sign-reader`、`transit-direction`、`speaker-focus`、`teleprompter-gaze`。注意力系 `chat-catchup`(SO01)、`standup-echo`(SO04)、`meeting-filter`(FI04)、`talk-replay`(RE02)。
- 第2段階 40：画像を見て質問するクラスター / 文字を読んで登録するクラスター / メモ・リマインダーのクラスター / 字幕・文字起こしのクラスター / 画面・番号を読み取るクラスター（明細はレポートを参照）。
- 第3段階：残りの番号付き Agent（艦隊122個のうち68個。ルート README の凡例のカウント88には JP/KR の現役20個が含まれる）。
- 事前スクリーニングの教訓：路縁の段差 CC07 `last-sentence` は立項時に「字幕を再生できる」ことで慧眼と区別したが、SO01 の基準では区別は成り立たない。新しい立項で「内蔵機能のある部分特性」を区別に使うものは、この skill を先に通してから着手する。

## バージョン反復ルール

この skill はバージョン番号付きで反復する。変更の際は必ず次の3つを同時に行う：バージョン番号を上げる、下記の変更履歴に1条追加する、レポートに根拠とした skill のバージョンを明記する。

- **PATCH（x.y.Z）**：文言、例、手順の細部の修正。判定基準とベースラインは変わらない。
- **MINOR（x.Y.0）**：ベースラインへの項目の追加・削除、判定基準への新しい場合の補足、手順へのステップの追加 ― 段階が変わる可能性があるため、影響を受ける Agent を変更履歴に明記しなければならない。
- **MAJOR（X.0.0）**：段階体系や基準の根本的な変化（GO が判定基準を変える場合など）。全艦隊を新しい基準で並べ替え、バッジをすべて同期しなければならない。
